# CSS 动画缓动曲线指南：从物理直觉到 39 种曲线选型

写 CSS 过渡动画时，很多人习惯随手写下 `transition: all 0.3s ease`，或者直接用 `linear`。做出来的界面明明帧率跑满了 60fps，点起来却总觉得发木、迟钝，甚至像幻灯片切换一样生硬。

问题往往不在动画时长，而在**缓动曲线**（Easing Function）。

现实生活里，没有任何有重量的物体能瞬间从静止变成匀速运动，也没有什么物体能在高速移动中突然定格而不产生惯性。==缓动曲线的作用，就是在屏幕上模拟物体的惯性、摩擦力与弹性。==

面对动效库里密密麻麻的三十多种缓动函数，死记硬背参数没什么意义。只要顺着**看懂曲线走势、定好加减速方向、挑对陡峭档位、处理终点停靠**这四个步骤捋一遍，基本就能凭直觉挑出最合适的那条曲线。

## 一、怎么看懂缓动曲线图

在浏览器开发者工具或动效文档里，经常能看到一张横轴为 `t`、纵轴为 `y` 的正方形曲线图。不少人容易把它误当成元素在屏幕上的“运动轨迹图”，其实它画的是**时间流逝与位移进度的对应关系**：

- **横轴 `t`**（Time，范围 `0.0 → 1.0`）：代表动画时间的流逝比例。`t = 0` 是动画刚开始的那一刻，`t = 1` 是动画结束的时刻。**时间永远向右匀速推进，不能倒流**，因此 `cubic-bezier(x1, y1, x2, y2)` 里的两个时间坐标 `x1` 和 `x2` 必须落在 `[0, 1]` 之间。
- **纵轴 `y`**（Progress，范围 `0.0 → 1.0`，允许越界）：代表动画属性的完成进度。`y = 0` 是起点状态（比如底部抽屉藏在屏幕外 `translateY(100%)`），`y = 1` 是终点状态（抽屉完全展开 `translateY(0%)`）。

拿到一条陌生的缓动曲线，只需要看三个地方，就能在脑子里还原出它的真实运动节奏：

### 1. 斜率代表速度：越陡越快，越平越慢

位移对时间的导数就是瞬时速度（$v = dy / dt$）。落到曲线图上，==某一点的切线越陡峭（接近垂直），说明那一刻运动速度越快；切线越平缓（接近水平），说明那一刻几乎处于停滞或慢速滑行状态。==

- 如果曲线在左下角起点处几乎贴着竖线往上冲，说明动画在点击瞬间**毫不拖沓地快速启动**；
- 如果曲线在右上角终点处慢慢贴近水平线，说明元素在停稳前有一段细腻的**减速刹车**。

### 2. 频闪点距代表加减速：稀疏是快，密集是慢

在静态文档或打印出来的纸张上没法播放动画，动效设计里常用**等时间间隔频闪快照**（Stroboscopic Trail）来观察速度变化。假设每隔 10% 的时间（`t = 0.1, 0.2, ..., 0.9`）给移动中的方块拍一张快照并留下一枚圆点：

- **圆点间距越稀疏**：说明在同样的 10% 时间内跨过了很长一段距离，此时速度很快；
- **圆点间距越密集**：说明每过 10% 时间只往前挪了一丁点，此时正在减速收尾。

### 3. 冲出顶线代表过冲：越过终点再回弹

虽然时间轴 `x` 不能超出 `[0, 1]`，但纵轴进度 `y` 的控制点 `y1`、`y2` 可以小于 `0` 或大于 `1`：

- 当曲线向上拱起、冲出顶部 `y = 1.0` 虚线（比如达到 `y = 1.12`）再回落到 `1.0` 时，元素会先**越过终点 12%，再柔和地退回原位**，也就是常说的“过冲回弹”（Overshoot）；
- 当曲线在左下角向下凹进 `y < 0` 的区域时，元素会在出发前先**往反方向微缩蓄力**，随后再向前弹出去。

## 二、按运动方向选曲线：进场、退场、屏内移动与匀速

挑缓动曲线的第一步不是纠结具体的贝塞尔数值，而是先看**元素与屏幕视野的关系**。下方的交互卡片把四种基础方向放在一起做了对比（点击任意一行或右上角按钮即可播放，轨道上的半透明圆点就是每 10% 时间的频闪快照）：

同样是加减速，为什么进场适合用 `ease-out`，退场却适合用 `ease-in`？这跟人眼的注意力习惯直接相关：

### 1. 元素进场（从无到有）：用 `ease-out`（先快后慢）

当用户点击按钮唤出弹窗、抽屉或下拉菜单时，最需要的是**及时的视觉响应**。

`ease-out` 在 `t = 0` 的瞬间初速度最大，手指刚抬起，弹窗已经跃入视野中央，给人一种界面干脆、跟手的直觉；到了后半段再平稳减速停下，就像车辆慢慢刹停在面前一样自然。

反过来，如果把进场动画写成 `ease-in`（先慢后快），点击后的前 150ms 元素几乎原地不动，用户很容易觉得“刚才那一下是不是没点上”，紧接着元素又在最后关头全速撞向终点突然停死，观感非常生硬。

### 2. 元素退场（从有到无）：用 `ease-in`（先慢后快）

当用户点下关闭按钮或遮罩层，准备关掉一个弹窗、划走一张卡片时，这个元素的任务已经结束了，视线只想让它尽快腾出地方。

`ease-in` 在短暂起步后持续加速飞出屏幕边缘。因为它离开视野（或透明度降为 `0`）时正处于最快速度，人眼根本不需要看清它在屏幕外面是怎么停下来的，干脆地加速消失反而最利索。==退场动画的时长一般比进场短 20%~30%==（比如抽屉展开用 `300ms ease-out`，收起只需 `200ms ease-in`）。

### 3. 屏内位置切换（从 A 到 B）：用 `ease-in-out`（慢-快-慢）

如果一个元素既没有飞入屏幕，也没有离开屏幕，而是**起点和终点都在视线范围内**（比如 Tab 栏底部的指示条左右滑动、手风琴折叠面板展开收起、悬浮按钮从左侧吸附到右侧）：

此时眼睛会全程盯着它从起点挪到终点。如果用 `ease-out`，起步那一下会显得太猛；如果用 `ease-in`，到达终点时又像撞了墙。只有前半程柔和加速、中段快速跨越、后半程平稳减速的节奏，才符合平时把杯子从桌子左边推到右边的自然手感。

在实际项目里，标准的 `ease-in-out`（`cubic-bezier(0.42, 0, 0.58, 1)`）前半段加速偏慢，通常更推荐用浏览器默认的 `ease`（`cubic-bezier(0.25, 0.1, 0.25, 1)`）或 Material 规范里的 `fastOutSlowIn`（`cubic-bezier(0.4, 0, 0.2, 1)`）。这两条曲线把加速过程缩短到了前 20% 的时间，留出 80% 的时间慢慢减速，响应更灵敏。

### 4. 持续循环与颜色过渡：用 `linear`（匀速）

`linear` 从头到尾速度恒定，没有任何惯性缓冲。如果拿它去做弹窗缩放或抽屉位移，看起来就像机械臂一样僵硬。

==除了无限循环的旋转图标（Loading Spinner）、进度条走字、跑马灯滚动，以及单纯的颜色或透明度渐变之外，普通的 UI 位置移动与缩放尽量避开 `linear`。==

## 三、缓出曲线的 6 个陡峭度档位：从 `Sine` 到 `Expo`

确定了进场用 `ease-out` 之后，打开动效库还是会看到一长串名字带 `easeOut` 的函数：`Sine`、`Quad`、`Cubic`、`Quart`、`Quint`、`Expo`、`Circ`。它们之间差在哪？

其实它们对应着**数学幂次从 1 级到 6 级的陡峭程度**。幂次越高，前 20% 时间内冲出去的距离占比就越大，后 80% 时间的减速滑行尾巴就越长：

<CssEasingDemo mode="power" />

平时写样式时，可以根据**元素移动的物理距离**（像素跨度）来挑选对应的档位：

1. **1 级 · `easeOutSine`（正弦缓出）**：斜率变化非常平缓，离 `linear` 只差一点点。适合**不涉及位置移动的属性**，比如背景色过渡（`background-color`）、阴影深浅变化（`box-shadow`）和透明度淡入（`opacity`）。
2. **2 级 · `easeOutQuad`（二次方缓出，$1 - (1-t)^2$）**：加减速很温和。适合**短距离微交互**（位移 `< 40px`），比如按钮悬停上浮 `2px`、开关拨片滑动、Tooltip 小提示框浮现。
3. **3 级 · `easeOutCubic`（三次方缓出，$1 - (1-t)^3$）**：==最稳妥的日常默认曲线==。拿不准用哪条时，选 `cubic-bezier(0.215, 0.61, 0.355, 1)` 基本不会出错。它的起步速度与收尾缓冲比较均衡，适合大多数卡片入场、居中模态框（Modal）和下拉菜单。
4. **4 级 · `easeOutQuart`（四次方缓出，$1 - (1-t)^4$）**：起步更果断，末端的阻尼减速感更强。适合**中等跨度的面板**（位移 `100px ~ 400px`），比如移动端底部半屏抽屉（Bottom Sheet）或侧边栏展开。
5. **5 级 · `easeOutQuint`（五次方缓出，$1 - (1-t)^5$）与 `easeOutCirc`（圆弧缓出）**：前 20% 时间就能跑完 75% 以上的路程。适合**长距离跨屏移动**（`> 400px`），比如全屏页面推入、大图画廊切换。
6. **6 级 · `easeOutExpo`（指数级缓出，$1 - 2^{-10t}$）**：几乎在点击瞬间就窜到了终点附近，紧接着是一段很长的慢速微滑。用 `easeOutExpo` 时，**动画时长最好拉长到 `450ms ~ 600ms`**；如果只给 `200ms`，前半段快到肉眼根本捕捉不到，看起来就跟直接闪现没区别了。

## 四、终点停靠方式：平滑刹停、微过冲回弹与物理弹簧

除了刚好停在 `100%` 终点的曲线，有时我们希望界面显得活泼一点、带点弹性，这时就会用到能够越过终点或者发生多次反弹的物理曲线：

<CssEasingDemo mode="overshoot" />

这几种终点停靠方式在写代码时有几个需要注意的地方：

### 1. 微过冲回弹：`easeOutBack`

`easeOutBack`（`cubic-bezier(0.175, 0.885, 0.32, 1.275)`）把第二个控制点的纵坐标设成了 `y2 = 1.275`，让元素快到终点时因为“惯性”往前多冲出 8%~10% 左右，再退回 `100%` 终点。

它很适合用在**居中弹出的活动弹窗、气泡菜单（Popover）、徽章解锁、顶部 Toast 滑下**这类四面留白的独立元素上。

但要注意**贴边组件的底部穿帮问题**：==贴着屏幕边缘滑出的底部抽屉或侧边栏，不要直接对 `translateY` 用 `easeOutBack`。== 因为底部抽屉从 `translateY(100%)` 移到 `translateY(0%)` 时，如果向上多冲出 10% 变成 `translateY(-10%)`，抽屉底边就会脱离屏幕底部，露出后面黑乎乎的遮罩层背景。如果确实想给底部抽屉加一点回弹，需要在抽屉底部多留出 `50px` 的同色内边距遮住穿帮区域。

### 2. 弹簧振荡 `elasticOut` 与落地反弹 `bounceOut`

传统的 `cubic-bezier()` 只有两个控制点，最多只能拐两个弯，表达不了来回摆动好几次的弹簧（`Elastic`）或连续触底反弹的小球（`Bounce`）。

以前在网页里做这两种效果，要么引 JS 动画库，要么手写一大串 `@keyframes`。现在主流浏览器（Chrome 113+、Edge 113+、Safari 17.2+、Firefox 112+）都已经原生支持 **CSS `linear()` 多点分段缓动函数**，一行样式就能写出逼真的弹簧与反弹：

```css
/* 1. 弹簧缓出 (elasticOut)：冲过终点 1.0 后围绕终点来回衰减摆动 */
.spring-badge {
  transition: transform 800ms linear(
    0, 0.57 7%, 1.15 16%, 1.09 22%, 0.93 32%,
    0.98 42%, 1.03 50%, 0.99 65%, 1.004 80%, 1
  );
}

/* 2. 落地反弹缓出 (bounceOut)：撞到 1.0 终点地面后向内多次弹起（不会越过 1.0） */
.falling-coin {
  transition: transform 900ms linear(
    0, 0.06 9%, 0.25 18%, 0.56 27%, 1 36%,
    0.81 45%, 0.75 54%, 0.81 63%, 1 72%,
    0.94 81%, 1 90%, 0.98 95%, 1
  );
}
```

区分这两条曲线很简单：`elasticOut` 是**穿过终点线（`y > 1.0`）前后晃动**，像挂在弹簧上的挂件；`bounceOut` 是**撞上 `y = 1.0` 地面后往回（`y < 1.0`）弹起**，绝对不会越过 `1.0` 边界，像掉在地板上的乒乓球。这两类动画动静很大，点缀在点赞红心、消息铃铛摇晃、金币掉落这类小图标上刚好，不要用在大面积的弹窗或页面切换上。

## 五、常见 UI 组件动效参数速查与实现细节

缓动曲线要跟合适的**动画时长**（Duration）搭在一起才自然。下面整理了日常开发里最常碰到的几类组件参数，写全局样式变量时可以直接参考：

| UI 组件 / 交互场景 | 动作方向 | 推荐曲线名称 | 标准 CSS 参数值 | 推荐时长 | 选型考量 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **按钮 / 卡片 Hover 态** | 状态微调 | `easeOutQuad` | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` | `150ms ~ 200ms` | 位移距离很短、触发频繁，需要轻快响应 |
| **Tooltip / 下拉小菜单** | 展开进场 | `easeOutCubic` | `cubic-bezier(0.215, 0.61, 0.355, 1)` | `180ms ~ 220ms` | 配合 `scale(0.95 -> 1)` 快速浮现 |
| **居中模态框 (Modal)** | 弹出进场 | `easeOutBack` 或 `easeOutCubic` | `cubic-bezier(0.175, 0.885, 0.32, 1.275)` | `250ms ~ 300ms` | 轻微过冲让弹窗显得更轻盈 |
| **居中模态框 (Modal)** | 关闭退场 | `easeInQuad` 或 `easeInCubic` | `cubic-bezier(0.55, 0.085, 0.68, 0.53)` | `180ms ~ 200ms` | 加速离场，比进场快约 30% |
| **底部抽屉 / 侧边栏** | 滑入展开 | `easeOutQuart` 或 `easeOutQuint` | `cubic-bezier(0.165, 0.84, 0.44, 1)` | `300ms ~ 380ms` | 初速度充沛，末端阻尼收尾贴合系统手感 |
| **底部抽屉 / 侧边栏** | 滑出收起 | `easeInCubic` | `cubic-bezier(0.55, 0.055, 0.675, 0.19)` | `220ms ~ 260ms` | 干脆收起，不越界穿帮 |
| **Tab 指示条 / 折叠面板** | 屏内位移 | `fastOutSlowIn` | `cubic-bezier(0.4, 0, 0.2, 1)` | `250ms ~ 300ms` | 20% 加速配 80% 减速，屏内滑动最顺畅 |
| **Toast 顶部轻提示** | 滑入停留 | `easeOutBack` | `cubic-bezier(0.175, 0.885, 0.32, 1.275)` | `300ms` | 轻巧弹下吸引余光注意 |
| **Loading 旋转 / 进度条** | 持续循环 | `linear` | `linear` | `800ms ~ 1200ms` | 首尾速度一致，避免一顿一顿的停滞感 |

### 写 CSS 动画时容易忽略的三个细节

1. **尽量只对 `transform` 和 `opacity` 做过渡，避开 `width`、`height`、`top`、`left`**：
   对宽高或定位边距做动画，浏览器每一帧都要重新计算页面布局（Reflow / Layout），在低配手机上很容易掉帧；而 `transform`（平移、缩放、旋转）和 `opacity` 直接走 GPU 合成器线程，即使同时跑多条复杂的贝塞尔曲线也很流畅。
2. **用 `easeOutBack` 时，把 `transform` 和 `opacity` 的过渡拆开写**：
   如果一个弹窗同时对 `transform: scale()` 和 `opacity` 做过渡，又偷懒合写成了 `transition: all 300ms cubic-bezier(0.175, 0.885, 0.32, 1.275)`，那么在过冲阶段 `opacity` 会被算成 `1.275` 并被浏览器强行截断在 `1.0`，导致透明度提前到顶。分开声明会细腻很多：
   ```css
   .modal-enter {
     transition:
       transform 300ms cubic-bezier(0.175, 0.885, 0.32, 1.275),
       opacity 200ms ease-out;
   }
   ```
3. **加上 `prefers-reduced-motion` 照顾对大幅动效敏感的用户**：
   有些用户在看到高频缩放或弹簧晃动时容易头晕，在操作系统的无障碍设置里会开启“减弱动态效果”。在全局样式里加上这段媒体查询，就能自动为这部分用户关掉多余动画：
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, *::before, *::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
     }
   }
   ```
