# CSS 动画缓动曲线完全指南：从物理直觉到 39 种曲线实战选型

写 CSS 过渡动画时，很多开发者习惯随手写下 `transition: all 0.3s ease`，或者干脆用 `linear` 一把梭。做出来的界面明明帧率跑满了 60fps，用户点起来却总觉得发木、迟钝，甚至像 PPT 切换一样生硬。

问题的根源通常不在动画时长，而在**缓动曲线（Easing Function）**。

现实世界里没有任何有质量的物体能够瞬间从零加速到匀速，也没有任何物体能在高速运动中瞬间静止而不产生惯性冲击。==缓动曲线的本质，就是在数字屏幕上模拟现实世界的质量、摩擦力与弹簧惯性。==

这篇文章把常见的 39 种经典缓动曲线拆解为四个递进维度：**怎么看懂曲线图、怎么选加减速方向、怎么挑陡峭度级别、怎么控制终点回弹**。文内嵌入了可交互对比面板，同时针对纸质打印与 PDF 导出做了专门的频闪轨迹排版，无论在线调试还是打印成速查手册都能直接对照使用。

## 一、三秒读懂缓动曲线：斜率即速度，点距即节奏

在浏览器开发者工具或动效文档里，我们经常看到一张横轴为 `t`、纵轴为 `y` 的正方形曲线图。很多初学者容易把这张图误当成元素在屏幕上的“运动轨迹图”，其实它是一张**时间与位移进度的映射图**：

- **横轴 `t`（Time，范围 `0.0 → 1.0`）**：代表动画时间的流逝比例。`t = 0` 是动画刚开始的瞬间，`t = 1` 是动画结束的时刻。**时间永远向右匀速前进，不能倒流**，因此 `cubic-bezier(x1, y1, x2, y2)` 中的两个时间控制点 `x1` 和 `x2` 必须严格限制在 `[0, 1]` 区间内。
- **纵轴 `y`（Progress，范围 `0.0 → 1.0`，允许越界）**：代表动画属性的完成进度。`y = 0` 是起点状态（例如抽屉隐藏在底部 `translateY(100%)`），`y = 1` 是终点状态（抽屉完全展开 `translateY(0%)`）。

拿到任何一条陌生的缓动曲线，只需要看懂以下三个几何特征，就能在脑海中还原出它的真实运动手感：

### 1. 看切线斜率：越陡越快，越平越慢

物理学中，位移对时间的导数就是瞬时速度（$v = dy / dt$）。反映在曲线图上，==某一点的切线越陡峭（接近垂直），代表那一刻运动速度越快；切线越平缓（接近水平），代表那一刻几乎处于停滞或微滑状态。==

- 如果曲线在左下角起点处几乎垂直向上冲，说明动画在点击瞬间**零延迟爆发启动**；
- 如果曲线在右上角终点处慢慢贴近水平线，说明元素在停靠前经历了细腻的**阻尼刹车**。

### 2. 看频闪采样点间距：稀疏代表疾驰，密集代表刹车

在静态文档或打印纸张上没法播放动画，动效设计师常用**等时间间隔频闪快照（Stroboscopic Trail）**来表达速度变化。假设每隔 10% 的时间（`t = 0.1, 0.2, ..., 0.9`）给运动中的方块拍一张快照并留下一个圆点：

- **圆点间距越稀疏**：说明在相同的 10% 时间内跨过了极长的距离，此刻速度极快；
- **圆点间距越密集**：说明每过 10% 时间只挪动了一点点位置，此刻正在减速收尾。

### 3. 看是否越出 `y = 1.0` 边界：凸出顶线即“过冲回弹”

虽然时间轴 `x` 不能超出 `[0, 1]`，但纵轴进度 `y` 的控制点 `y1`、`y2` 完全可以小于 `0` 或大于 `1`：

- 当曲线向上拱起、冲出顶部 `y = 1.0` 虚线（例如达到 `y = 1.12`）再回落到 `1.0` 时，元素会先**冲过目标终点 12%，再柔和地退回终点**，这就是“过冲回弹（Overshoot）”；
- 当曲线在左下角向下凹陷到 `y < 0` 区域时，元素会在出发前先**向反方向微缩蓄力**，随后再向前弹射出去。

## 二、动效方向的三大黄金铁律：进场、退场与屏内过渡

选缓动曲线的第一步不是挑具体的数学公式，而是先根据**元素与屏幕视野的关系**确定加减速方向。下方的交互卡片展示了四种基础方向的同屏对比（点击任意轨道或右上角按钮即可触发对比，轨道上的半透明圆点即为每 10% 时间的频闪快照）：

为什么同样是曲线，`ease-out` 适合进场，而 `ease-in` 适合退场？背后对应着人类视觉感知的三条铁律：

### 铁律 1：进场动画（从无到有）必须用 `ease-out`（缓出：先快后慢）

当用户点击按钮呼出弹窗、抽屉或下拉菜单时，人眼最渴望得到**即时的交互反馈**。

- **为什么选 `ease-out`**：它在 `t = 0` 瞬间拥有极高的初速度，用户手指刚抬起，元素已经冲进视野中央，给人“系统响应极快、极其跟手”的直觉；随后在后半程平滑减速停靠，就像一辆好车稳稳刹停在面前，不会造成突兀的撞击感。
- **反例警告**：如果把进场动画写成 `ease-in`（先慢后快），用户点击后前 150ms 元素几乎没动静，会让人误以为“点击没生效、页面卡了”，紧接着元素又在最后关头全速砸向终点戛然而止，体验非常糟糕。

### 铁律 2：退场动画（从有到无）应当用 `ease-in`（缓入：先慢后快）

当用户点击关闭按钮或遮罩层销毁一个弹窗、滑走一张删除卡片时，这个元素已经完成了它的使命，用户希望它尽快把屏幕空间让出来。

- **为什么选 `ease-in`**：起始阶段短暂启动后，元素持续加速飞出屏幕边界。由于它冲出屏幕边缘（或透明度降为 `0`）时处于最高速度，人眼根本不需要看它“如何减速停在屏幕外”，干脆利落的加速离场反而最清爽。
- **时长折半原则**：==退场动画的持续时间通常应比进场动画短 20%~30%==（例如抽屉进场用 `300ms ease-out`，收起退场只需 `200ms ease-in`）。

### 铁律 3：屏内位移与形变必须用 `ease-in-out`（缓入缓出：慢-快-慢）

如果一个元素既没有进入屏幕，也没有离开屏幕，而是**起点和终点都在用户视线范围内**（例如 Tab 底部高亮滑块左右切换、手风琴折叠面板展开收起、悬浮球从左吸附到右）：

- **为什么选 `ease-in-out`**：用户的眼睛会全程盯着它的起点和终点。如果用 `ease-out`，起跳瞬间太突兀；如果用 `ease-in`，停靠瞬间像撞墙。只有前半程柔和加速、中段高速穿越、后半程平稳刹车的对称节奏，才符合真实物体在桌面上从 A 点挪到 B 点的自然运动规律。
- **更优进阶选择**：标准 `ease-in-out`（`cubic-bezier(0.42, 0, 0.58, 1)`）前半段加速略慢，实战中更推荐使用浏览器默认的 `ease`（`cubic-bezier(0.25, 0.1, 0.25, 1)`）或 Material Design 标准曲线 `fastOutSlowIn`（`cubic-bezier(0.4, 0, 0.2, 1)`）。它们的加速段更短（约占 20% 时间），减速段更长（约占 80% 时间），兼顾了响应速度与柔和停靠。

### 补充：什么时候才能用 `linear`（匀速）？

==除了无限循环的旋转图标（Loading Spinner）、进度条走字、跑马灯滚动，或者纯粹的颜色/透明度渐变之外，严禁在任何 UI 空间位移（`translate` / `scale`）中使用 `linear`。==

## 三、缓出曲线的 6 级陡峭度阶梯：从 `Sine` 到 `Expo` 怎么挑？

确定了“进场用 `ease-out`”之后，打开动效库一看，名叫 `easeOut` 的曲线竟然有七八种：`Sine`、`Quad`、`Cubic`、`Quart`、`Quint`、`Expo`、`Circ`。它们到底有什么区别？

简单来说，它们代表**数学幂次（陡峭度）从 1 级到 6 级的递增阶梯**。幂次越高，前 20% 时间内冲出的路程占比就越大，后 80% 时间的阻尼刹车尾巴就越长：

<CssEasingDemo mode="power" />

在实际项目中，可以根据**元素移动的物理距离（像素跨度）**来对号入座：

1. **1 级 · `easeOutSine`（正弦缓出）**：加速度变化极其微弱，最接近 `linear`。适合**非空间位移属性**（如背景色渐变 `background-color`、阴影浓淡 `box-shadow`、透明度过渡 `opacity`）。
2. **2 级 · `easeOutQuad`（二次方缓出，$1 - (1-t)^2$）**：轻柔舒适。适合**短距离微交互（位移 `< 40px`）**，比如按钮 Hover 上浮 `2px`、Switch 开关拨片、Tooltip 小气泡浮现。
3. **3 级 · `easeOutCubic`（三次方缓出，$1 - (1-t)^3$）**：==全场景黄金万金油==。如果你拿不准该用哪条曲线，无脑选 `cubic-bezier(0.215, 0.61, 0.355, 1)` 准没错。它在启动爆发力与收尾平稳度之间达到了最佳平衡，适合绝大多数卡片入场、居中弹窗（Modal）和下拉列表。
4. **4 级 · `easeOutQuart`（四次方缓出，$1 - (1-t)^4$）**：干脆利落，阻尼感明显。非常适合**中等跨度容器（位移 `100px ~ 400px`）**，如移动端底部半屏抽屉（Bottom Sheet）、侧边导航栏（Drawer）滑出。
5. **5 级 · `easeOutQuint`（五次方缓出，$1 - (1-t)^5$）与 `easeOutCirc`（圆弧缓出）**：爆发力极强，前 20% 时间就能走完 75% 以上的路程。适合**长距离跨屏位移（`> 400px`）**，比如全屏页面推入、画廊大图切换。
6. **6 级 · `easeOutExpo`（指数级缓出，$1 - 2^{-10t}$）**：闪电般起步，随后进入漫长的悬浮微滑。具有强烈的现代先锋科技感，常用于数字大屏或高端产品落地页。**注意**：使用 `easeOutExpo` 时，动画时长必须拉长到 **`450ms ~ 600ms`**，如果只给 `200ms`，前段速度会快到肉眼看不清，变成生硬的瞬移。

## 四、终点形态与物理曲线：精准停靠 vs 微过冲 `Back` vs 弹簧 `Elastic`

除了平滑刹停在 `100%` 终点的曲线外，当我们需要传递“欢快、灵动、有弹性”的品牌情绪时，就会用到能够越过终点或发生多次碰撞的物理曲线：

<CssEasingDemo mode="overshoot" />

这四类终点形态在工程实现与适用边界上有着严格的区分：

### 1. 微过冲回弹：`easeOutBack`（三次贝塞尔即可原生实现）

`easeOutBack`（`cubic-bezier(0.175, 0.885, 0.32, 1.275)`）通过把第二个控制点的纵坐标设为 `y2 = 1.275`，让元素在接近终点时因为“惯性太大”稍微刹不住车，向前冲出约 8%~10% 的距离，然后再优雅地缩回 `100%` 终点。

- **最佳场景**：居中弹出的营销活动弹窗、气泡提示框（Popover）、成就徽章解锁、购物车图标加入动效。
- **使用红线（贴边穿帮问题）**：==严禁在贴边抽屉（Bottom Sheet / Side Drawer）上直接使用 `easeOutBack` 位移！== 因为当底部抽屉从 `translateY(100%)` 移动到 `translateY(0%)` 时，如果发生 10% 的过冲，抽屉会继续向上冲到 `translateY(-10%)`，导致**抽屉底部的边缘脱离屏幕底边，漏出底下黑乎乎的遮罩层背景**（俗称“底部穿帮”）。若一定想给底部抽屉加过冲，必须在抽屉底部额外增加 `50px` 同色延展内边距（Padding Skirt）遮挡穿帮区域。

### 2. 弹簧振荡 `elasticOut` 与重力反弹 `bounceOut`（需用现代 CSS `linear()`）

传统的 `cubic-bezier()` 只有两个控制点，最多只能产生一次波峰和一次波谷，无法表达多次往复衰减的弹簧（`Elastic`）或多次触底反弹的小球（`Bounce`）。

过去在 Web 端实现这两种曲线必须引入 JS 动画库或编写冗长的 `@keyframes` 关键帧。而现在，所有现代主流浏览器（Chrome 113+、Edge 113+、Safari 17.2+、Firefox 112+）均已原生支持 **CSS `linear()` 多点分段缓动函数**，只需一行 CSS 即可还原真实的弹簧与反弹：

```css
/* 1. 弹簧缓出 (elasticOut)：越过终点 1.0 来回正弦衰减振荡 */
.spring-badge {
  transition: transform 800ms linear(
    0, 0.57 7%, 1.15 16%, 1.09 22%, 0.93 32%,
    0.98 42%, 1.03 50%, 0.99 65%, 1.004 80%, 1
  );
}

/* 2. 重力反弹缓出 (bounceOut)：撞击 1.0 终点地面后向内多次弹起（绝不越过 1.0） */
.falling-coin {
  transition: transform 900ms linear(
    0, 0.06 9%, 0.25 18%, 0.56 27%, 1 36%,
    0.81 45%, 0.75 54%, 0.81 63%, 1 72%,
    0.94 81%, 1 90%, 0.98 95%, 1
  );
}
```

- **两者的核心区别**：`elasticOut` 是**穿过终点线（`y > 1.0`）前后摆动**，像挂在弹簧上的吊坠；而 `bounceOut` 是**撞到 `y = 1.0` 墙壁后向内（`y < 1.0`）弹起**，永远不会越过 `1.0` 边界，像掉在大理石地面上的乒乓球。
- **克制使用原则**：`elastic` 和 `bounce` 视觉存在感极强，只适合用于**小尺寸视觉焦点**（如点赞红心放大、游戏金币掉落、错误输入框左右摇晃），切勿用于大面积页面切换或正文列表，否则会让用户产生强烈的眩晕感。

## 五、Web UI 实战场景选型速查表与 3 大避坑红线

在日常前端开发中，缓动曲线必须与恰当的**动画时长（Duration）**配合才能发挥效果。下表整理了高频 UI 组件的黄金组合参数，可直接作为团队设计规范（Design Token）落地：

| UI 组件 / 交互场景 | 动作方向 | 推荐曲线名称 | 标准 CSS 参数值 | 推荐时长 | 选型理由 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **按钮 / 卡片 Hover 态** | 状态微调 | `easeOutQuad` | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` | `150ms ~ 200ms` | 距离短、触发极高频，需即时轻巧响应 |
| **Tooltip / 下拉小菜单** | 展开进场 | `easeOutCubic` | `cubic-bezier(0.215, 0.61, 0.355, 1)` | `180ms ~ 220ms` | 配合 `scale(0.95 -> 1)` 迅速清晰呈现 |
| **居中模态框 (Modal)** | 弹出进场 | `easeOutBack` 或 `easeOutCubic` | `cubic-bezier(0.175, 0.885, 0.32, 1.275)` | `250ms ~ 300ms` | 微过冲赋予弹窗轻盈的呼吸感与聚焦感 |
| **居中模态框 (Modal)** | 关闭退场 | `easeInQuad` 或 `easeInCubic` | `cubic-bezier(0.55, 0.085, 0.68, 0.53)` | `180ms ~ 200ms` | 加速消失，比进场快约 30%，不拖泥带水 |
| **底部抽屉 / 侧边栏** | 滑入展开 | `easeOutQuart` 或 `easeOutQuint` | `cubic-bezier(0.165, 0.84, 0.44, 1)` | `300ms ~ 380ms` | 强初速度配合长阻尼收尾，贴合原生系统手感 |
| **底部抽屉 / 侧边栏** | 滑出收起 | `easeInCubic` | `cubic-bezier(0.55, 0.055, 0.675, 0.19)` | `220ms ~ 260ms` | 干脆利落收起，绝不越界穿帮 |
| **Tab 导航指示器 / 折叠面板** | 屏内位移 | `fastOutSlowIn` | `cubic-bezier(0.4, 0, 0.2, 1)` | `250ms ~ 300ms` | 20% 加速 + 80% 减速，屏内穿梭最顺滑 |
| **Toast 顶部轻提示** | 滑入停留 | `easeOutBack` | `cubic-bezier(0.175, 0.885, 0.32, 1.275)` | `300ms` | 轻巧弹下吸引余光注意，且不打断主流程 |
| **Loading 旋转 / 进度条** | 持续循环 | `linear` | `linear` | `800ms ~ 1200ms` | 首尾无缝衔接，防止周期性停顿卡顿感 |

### 生产环境必守的 3 条动效红线

1. **永远只对合成层属性（`transform` 与 `opacity`）做缓动动画**：
   不要对 `width`、`height`、`top`、`left`、`margin` 使用复杂的缓动曲线。修改几何布局属性会在每一帧触发浏览器的主线程重排（Reflow/Layout），在低端设备上极易掉帧卡顿；而 `transform: translate / scale` 和 `opacity` 全程由 GPU 合成器线程独立运算，哪怕同时跑几十个 `cubic-bezier` 曲线也能稳住 60/120fps。
2. **不要把 `opacity` 塞进带过冲的 `easeOutBack` 里**：
   如果一个弹窗同时过渡 `transform: scale()` 和 `opacity`，且共用了 `easeOutBack`（`y2 = 1.275`），那么在过冲阶段 `opacity` 会被计算为 `1.275` 并被浏览器强制截断（Clamp）在 `1.0`，导致透明度提前到顶、失去柔和感。更讲究的做法是分开声明：
   ```css
   .modal-enter {
     transition:
       transform 300ms cubic-bezier(0.175, 0.885, 0.32, 1.275),
       opacity 200ms ease-out;
   }
   ```
3. **尊重系统无障碍减弱动画偏好（`prefers-reduced-motion`）**：
   部分前庭神经敏感的用户在看到大幅度的过冲或弹簧动画时会产生生理性头晕。务必在全局样式表中加上无障碍兜底：
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, *::before, *::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
     }
   }
   ```
