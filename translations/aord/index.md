# 默认存活还是默认死亡？

> 原文：[Default Alive or Default Dead?](https://www.paulgraham.com/aord.html) · 作者：Paul Graham（2015年10月） · [查看英文原版](./en.md)

![默认存活还是默认死亡？](/images/aord/default-alive-vs-dead.webp)

每当我和一家已经运营了八九个月以上的创业公司交流时，我首先想搞清楚的问题几乎永远是同一个：==假设你们现有的开销保持不变，且营收增速维持在过去几个月的水平，光靠账上仅剩的这笔钱，你们能撑到实现盈利吗？或者换个更富戏剧性的问法：在默认情况下，你们是活还是死？==

令人震惊的是，绝大多数时候连创始人自己都答不上来。跟我聊过的创始人里，有一半根本不知道自己的公司目前处于“默认存活（Default Alive）”还是“默认死亡（Default Dead）”状态。

如果你也属于不清楚的那一半，特雷弗·布莱克威尔（Trevor Blackwell）做了一个很顺手的[在线计算器](http://growth.tlb.org/#)，你可以直接把数据填进去算一下。

我之所以一上来就要先问一家创业公司是“默认存活”还是“默认死亡”，是因为我们接下来的整场谈话完全取决于这个答案。如果公司处于默认存活状态，我们就可以畅谈那些雄心勃勃的新业务构想；如果它处于默认死亡状态，那我们恐怕得赶紧聊聊怎么救命了。既然明明知道眼下这条轨道走到头是死路一条，那到底该怎么帮他们跳出这条死亡轨道？

为什么极少有创始人清楚自己是默认存活还是默认死亡呢？在我看来，主要原因在于他们根本没有养成问自己这个问题的习惯。在创业最早期，问这个问题确实毫无意义，就好比跑去问一个三岁小孩将来打算怎么养活自己一样荒唐。可随着公司一天天长大，这个问题就会不知不觉从“毫无意义”变成“生死攸关”。而这种性质的悄然转换，往往会打得人们措手不及。

对此我提出一个解决方案：**与其等到太晚才开始追问自己是默认存活还是默认死亡，不如从太早的时候就开始问。** 我们很难精确界定这个问题到底在哪一天发生极性反转。但过早开始担心自己处于“默认死亡”状态，通常不会有什么大害处；相反，等到太晚才开始担心，却是致命的。

原因就在于我之前专门写文章剖析过的一种现象：“[致命夹击](https://www.paulgraham.com/pinch.html)（Fatal Pinch）”。==所谓的致命夹击，就是“默认死亡 + 增长缓慢 + 剩下的时间已经不够自救了”。== 而创始人们之所以会一头栽进这个死局，往往就是因为他们在滑向深渊的过程中浑然不觉。

创始人们不愿问自己“默认存活还是默认死亡”，还有另一个原因：他们想当然地以为后续再融资会是一件轻而易举的事。然而这种假设往往是错的；更糟的是，你越是把身家性命寄托在“肯定能融到下一轮”之上，这件事成真的概率就越低。

把冰冷的事实与一厢情愿的盼望剥离开来，或许能帮你保持清醒。别再用模糊的盲目乐观去憧憬未来了，试着把现状拆解开来，直白地对自己说一句：“我们目前处于默认死亡状态，但我们正指望着投资人来救命。”也许当你亲口把这句话念出来时，它会在你脑海里拉响同样刺耳的警报，就像它每次在我脑海里拉响警报那样。只要你足够早地拉响这记警报，你就完全有机会避开那场致命夹击。

诚然，如果你百分百能指望上投资人出手相救，哪怕处于默认死亡状态也是安全的。一般来说，投资人对你的兴趣大小，直接取决于你的增长斜率。如果你的营收呈现出极其陡峭的指数级增长（比方说一年翻五倍以上），哪怕你眼下还没实现盈利，你也确实可以开始指望投资人会对你感兴趣。[[1]](#f1n) 但投资人是一个极其善变的群体，你顶多只能“开始指望”他们，而绝不能把宝全押在他们身上。有时候，哪怕你的增长数据再亮眼，业务里的某个细枝末节也可能会突然吓跑投资人。因此，无论你的增长势头有多猛，你都绝不能把“继续融资”当成唯一的救命稻草；它顶多只能作为你的 A 计划。你手里必须永远备着一套 B 计划：你应当一清二楚地知道（最好白纸黑字写下来），万一融不到下一轮钱，你们具体需要采取哪些断腕措施才能活下来，以及一旦 A 计划进展不顺，到底要在哪一个精确的时间节点果断切换到 B 计划。

退一步讲，“快速增长”与“低成本精益运营”之间，远非许多创始人所以为的那样水火不容。==在真实的创业实践中，一家创业公司花钱的多少，与它增长的快慢之间，几乎不存在什么正相关关系。== 当一家创业公司实现爆发式增长时，通常是因为它的产品精准戳中了痛点，正面击中了某种巨大的真实需求；而当一家创业公司大把烧钱时，通常只是因为这产品研发或推销起来太昂贵，或者单纯因为他们花钱大手大脚。

如果你读到这里一直在认真思考，此刻你心里的疑问肯定不光是“如何避开致命夹击”，而是更进一步：“到底怎样才能避免陷入默认死亡？”这个问题的答案其实很简单：**别招人太快。对于拿了融资的创业公司而言，招人太快是迄今为止排名第一的头号杀手。** [[2]](#f2n)

创始人们总是给自己洗脑说，为了实现增长，必须赶紧扩招团队。但绝大多数人在这件事上犯的错，都是高估了招人的必要性，而不是低估了它。为什么会这样？一部分原因在于眼前要干的活实在太多了。天真的创始人以为，只要招来足够多的人手，所有积压的活自然就能干完。另一部分原因在于，放眼望去，那些成功的创业公司都拥有庞大的员工团队，于是大家便误以为“先把团队规模搞上去”是走向成功的必经之路。殊不知，成功创业公司庞大的员工规模，多半是业务高速增长之后的**结果**，而不是带来增长的**原因**。此外还有一部分原因在于，当业务增长缓慢时，创始人们往往不愿直面那个最扎心的真实原因：**他们的产品吸引力还远远不够。**

雪上加霜的是，刚刚拿到融资的创始人，往往还会受到投资方（VC）的极力怂恿去大肆招人。对于风险投资机构来说，“要么一飞冲天、要么速死出局（Kill-or-cure）”的激进策略是最符合他们利益的最优解，因为他们有投资组合效应（Portfolio effect）护体。用英语里的一句双关语来说，VC 最希望看到你“原地爆炸（Blow you up）”：要么业绩暴涨一飞冲天，要么迅速把钱烧光炸成灰烬。但作为创始人，你的利益激励机制跟 VC 截然不同。对你而言，压倒一切的第一要务是活下去。[[3]](#f3n)

下面我来还原一种创业公司最常见的标准死法：
创始团队做出了一款还算有点吸引力的产品，初期增长数据也挺体面。于是他们相当轻松地拿到了第一轮融资，因为几位创始人看起来既聪明又靠谱，商业点子听起来也合情合理。但由于产品仅仅停留在“还算有点吸引力”的程度，接下来的增长也就一直不温不火，远称不上惊艳。这时，创始人们开始说服自己：只要招一大批人进来，就能把增长顶上去。他们的投资人对此也拍手赞同。然而（正因为产品本身只有中规中矩的吸引力），期待中的爆发式增长始终没有到来。更要命的是，因为养了一大帮人，账上的现金跑道（Runway）正在以惊人的速度缩短。他们满心指望靠下一轮融资来救命；可到了这个时候，由于他们背着高昂的固定开销，增长却慢如蜗牛，在投资人眼里已经彻底失去了吸引力。最终，他们融不到新钱，公司宣告死亡。

这家公司当初真正该做的，是全力以赴去解决那个最根本的病灶：**产品本身的吸引力不够强。** 靠多招人几乎永远解决不了这个问题；恰恰相反，人招得越多，调头改产品的难度反而越大。在创业早期这个阶段，产品需要的是“快速演化迭代（Evolve）”，而不是按部就班地“添砖加瓦扩建（Built out）”；而要想让产品灵活演化，人越少通常越容易办到。[[4]](#f4n)

及早追问自己“默认存活还是默认死亡”，或许就能把你从这条不归路上拉回来。它拉响的刺耳警报，也许正好能抵消掉四面八方推着你盲目扩招的冲动，逼着你去另辟蹊径寻找真正的增长引擎：比如去亲手做那些“[无法规模化的笨事](https://www.paulgraham.com/ds.html)（Do things that don't scale）”，或者以只有创始人才具备的洞察力与魄力去彻底重塑产品。对于大多数创业公司而言，这些看似笨拙的路径，往往才是真正管用的增长之道。

当年 Airbnb 在 Y Combinator 孵化结束并拿到融资之后，足足等了四个月才招入第一名员工。在那四个月里，几位创始人确实累得像狗一样。但他们之所以累得半死，是因为他们正亲手把 Airbnb 一步步重塑、演化成今天这个取得惊人成功的有机体。

### 注释

<span id="f1n">**[1]**</span> 陡峭的用户使用量（Usage）增长同样能吸引投资人。因为从长远来看，营收终归会与用户使用量呈固定倍数关系，所以 $x\%$ 的使用量增长，在理论上预示着未来 $x\%$ 的营收增长。但在实际操作中，投资人会对仅仅停留在纸面预测上的未来营收打个折扣；因此如果你拿用户使用量作为核心指标，你就需要拿出比纯营收增速高得多的增长率，才能真正打动投资人。

<span id="f2n">**[2]**</span> 那些没有拿外部融资的创业公司，反而自动免于“招人太快”的死劫，原因很简单：他们压根没钱招人。但这绝不意味着为了避开过度招聘的陷阱，你就应该干脆拒绝融资；这就好比不能因为害怕变成酒鬼，就宣称滴酒不沾是世上唯一的出路一样。

<span id="f3n">**[3]**</span> 如果最终证实“VC 怂恿创始人盲目扩招的倾向，其实连 VC 自己的长远利益都损害了”，我也丝毫不会感到惊讶。因为 VC 们自己也算不清，在那些被高额烧钱直接拖死的创业公司当中，假如当初省着点花钱活下来，究竟有多少家原本能够跑出来大获成功。我的猜测是，这个比例相当可观。

<span id="f4n">**[4]**</span> 山姆·奥特曼（Sam Altman）在读完本文初稿后写道：

> “我觉得你应该把‘克制招人’这一点写得更重、更狠一些。毫不夸张地说，Y Combinator 历史上最成功的那批公司，在招人速度上从来都不是最快的；而衡量一名伟大创始人的重要标志之一，正是看他能否顶住这种盲目扩招的冲动。”

Gmail 之父保罗·布赫海特（Paul Buchheit）补充道：

> “我经常看到的另一个密切相关的毛病，是**过早规模化（Premature scaling）**：创始人们手里明明只有一个还没真正跑通的小业务（通常表现为单位经济模型一塌糊涂），却为了刷出好看的增长数字去强行放大规模。这跟盲目扩招如出一辙：一旦把摊子铺大了，想要修补业务模型的难度就会呈指数级上升，而且账上的现金会以极其恐怖的速度流干。”
