# 十年学会编程

> 原文：[Teach Yourself Programming in Ten Years](https://www.norvig.com/21-days.html) · 作者：Peter Norvig（2001年 / 2014年修订） · [查看英文原版](./en.md)

![十年学会编程](/images/21-days/ten-years-programming.webp)

## 为什么大家都这么急于求成？

走进任何一家书店，你都会看到一整排《24小时自学 Java》（*Teach Yourself Java in 24 Hours*）之类的畅销书，旁边还摆满了五花八门的同类变体，号称能在短短几天甚至几个小时内教会你 C 语言、SQL、Ruby 和算法。如果你去亚马逊的高级搜索里输入条件 `[书名包含: teach, yourself, hours, 出版年份晚于: 2000]`，足足能搜出 512 本这样的书。在排名前十的书里，有九本都是编程书（剩下唯一那本是教会计记账的）。要是把搜索词里的“自学（teach yourself）”换成“学会（learn）”，或者把“小时（hours）”换成“天（days）”，搜出来的结果也大同小异。

由此只能得出两个结论：要么是世人对于学编程这件事火急火燎到了极点，要么就是编程不知怎么回事，比世上其他任何手艺都好学得离谱。马蒂亚斯·费莱森（Felleisen）等人在他们的名著《[程序设计方法](http://www.ccs.neu.edu/home/matthias/HtDP2e/index.html)》（*How to Design Programs*）中，就对这种浮躁风气给出了一针见血的嘲讽：==“写出烂代码确实很容易。哪怕是彻头彻尾的**白痴（Idiots）**，也能在 **21 天**内学会怎么写烂代码，就算他们是纯正的**傻瓜（Dummies）**也不例外。”==（注：此处连用英文畅销速成书系 *Complete Idiot's Guide* 与 *For Dummies* 的双关梗。）著名极客漫画《Abstruse Goose》也画过[一幅令人捧腹的漫画](http://abstrusegoose.com/249)来吐槽这件事（漫画里想要在 21 天学会 C++ 的唯一办法，是在第 14611 天造出一台时光机穿越回第 21 天替换掉年轻时的自己）：

![如何在 21 天内自学 C++（Abstruse Goose 经典漫画）](/images/21-days/abstruse-goose-cpp-21-days.webp)

不妨让我们认真拆解一下，像《[24小时自学 C++](http://www.amazon.com/Sams-Teach-Yourself-Hours-5th/dp/0672333317/)》这样的书名究竟能意味着什么：

- **自学（Teach Yourself）：** 在短短 24 小时里，你根本没有时间亲手写出几个像样的大型程序，更没有时间从这些项目的成功与失败中汲取教训。你也没有时间与经验丰富的老程序员并肩协作，去体会真正泡在 C++ 工程环境里讨生活究竟是什么滋味。简而言之，24 小时根本不够你学到什么真东西。因此，这类书顶多只能带你混个脸熟、摸一下皮毛，绝不可能是深入骨髓的理解。正如英国诗人亚历山大·蒲柏（Alexander Pope）所言：“一知半解是一件危险的事（A little learning is a dangerous thing）。”
- **C++：** 在 24 小时里，你或许能突击背会一部分 C++ 的语法规则（前提是你本来就已经掌握了另一门编程语言），但你根本学不会到底该如何运用这门语言。说白了，假如你原本是一名 Basic 程序员，你确实可以在 24 小时内学会“用 C++ 的语法外壳，写出充满 Basic 味道的程序”，但你根本不可能领悟 C++ 真正强大和真正糟糕的地方分别在哪里。那折腾这一番图什么呢？图灵奖得主[艾伦·佩利](http://www-pu.informatik.uni-tuebingen.de/users/klaeren/epigrams.html)（Alan Perlis）曾有一句名言：==“一门不能改变你编程思维方式的语言，根本不值得去学。”== 当然，有一种现实情况情有可原：你手头急需完成某项特定任务，不得不跟某个现成工具打交道，因此必须临时现学一丁点 C++ 皮毛（更常见的情况是现学一点 JavaScript 或 Processing）。但如果是这样，你其实并不是在“学习如何编程”，你只是在学习如何搞定眼下那个具体任务罢了。
- **24 小时内（in 24 Hours）：** 很遗憾，这点时间远远不够，正如接下来这一节所要证明的那样。

## 用十年时间自学编程

众多认知心理学研究者（[Bloom (1985)](http://www.amazon.com/exec/obidos/ASIN/034531509X/)、[Bryan & Harter (1899)](#bh)、[Hayes (1989)](http://www.amazon.com/exec/obidos/ASIN/0805803092)、[Simon & Chase (1973)](#cs)）通过大量实证研究表明：无论在国际象棋、音乐作曲、电报收发、绘画、钢琴演奏、游泳、网球，还是在神经心理学与拓扑学研究等截然不同的领域，要想真正成长为一名专家，大约都需要耗费**十年**光阴。其中的核心秘诀在于**刻意练习（Deliberative practice）**：绝不是机械地把已经会做的事情重复一千遍，而是主动用那些“刚好略高于你当前能力极限”的任务去挑战自己，亲手尝试，在做的过程中以及做完之后复盘剖析自己的表现，并针对性地纠正每一个错误。然后周而复始，循环往复。在这条路上，根本不存在什么真正的捷径：哪怕是 4 岁就显露惊世才华的音乐神童莫扎特，也足足又磨砺了 13 年，才在 17 岁时开始谱写出真正具有世界级水准的杰作。再看流行音乐界，披头士乐队（The Beatles）看似是在 1964 年带着一连串冠军单曲登上艾德·沙利文秀（Ed Sullivan Show）而一夜爆红；但实际上，他们从 1957 年起就一直在利物浦和德国汉堡的地下小俱乐部里日夜驻唱打磨，而且尽管早年就收获了大众追捧，他们真正奠定乐史丰碑的第一张殿堂级专辑《佩珀军士的孤独之心俱乐部乐队》（*Sgt. Pepper's*），直到 1967 年才正式问世。

畅销书作家[马尔科姆·格拉德威尔](http://www.amazon.com/Outliers-Story-Success-Malcolm-Gladwell/dp/0316017922)（Malcolm Gladwell）在《异类》一书中让这一理念家喻户晓，只不过他聚焦的是“10,000 小时”，而不是“10 年”。现代新闻摄影之父亨利·卡蒂埃-布列松（Henri Cartier-Bresson，1908–2004）则给出了另一个维度的刻度：“你拍出的前 10,000 张照片，都是你最烂的作品。”（当然，老先生当年没料到数码相机的普及，如今有的人按着连拍键一个星期就能凑够一万张。）真正的炉火纯青甚至需要倾注毕生心血：英国文豪塞缪尔·约翰逊（Samuel Johnson，1709–1784）曾说：“任何领域的卓越境界，都唯有倾尽一生的辛勤劳作方能企及；想用更低廉的代价将其买下，纯属痴心妄想。”乔叟（Chaucer，1340–1400）也曾感叹：“人生如此苦短，技艺却需如此漫长的岁月去习得。”古希腊医学之父希波克拉底（Hippocrates，约公元前 400 年）更是留下了那句千古名言“人生苦短，技艺绵长（Ars longa, vita brevis）”；这句话的完整原文其实是：“人生苦短，技艺绵长，机缘转瞬即逝，尝试危机四伏，判断难如登天（Ars longa, vita brevis, occasio praeceps, experimentum periculosum, iudicium difficile）。”

当然，没有任何一个单一的数字能充当放之四海而皆准的终极答案：假设所有技能（比如编程、国际象棋、跳棋和器乐演奏）都需要花费完全相同的时间去精通，显然是不合情理的；假设每个人在精进路上耗费的时间分秒不差，也同样荒谬。正如刻意练习理论奠基人[安德斯·艾利克森](http://www.amazon.com/K.-Anders-Ericsson/e/B000APB8AQ/)（K. Anders Ericsson）教授所言：“在绝大多数专业领域里，哪怕是那些被公认为最具天赋的奇才，要想攀上最高水平的性能巅峰，所必须投入的时间长度依然惊人。所谓‘一万小时’，只是为了让你在数量级上有一个直观概念：我们谈论的是每周雷打不动地高强度投入 10 到 20 个小时、并且连续坚持好些年，哪怕是天赋最高的人也逃不过这个苦功。”

## 那么，你想成为一名程序员

下面是我为你开出的“编程精进配方”：

- **对编程产生真正的兴趣**，因为觉得好玩而去写代码。请确保自己始终能从中获得源源不断的乐趣，唯有如此，你才甘愿把那十年或一万个小时心甘情愿地投入进去。
- **动手写代码（Program）。** 最好的学习方式永远是“[边做边学](http://www.engines4ed.org/hyperbook/nodes/NODE-120-pg.html)（Learning by doing）”。用更学术的话来说：“一个人在特定领域的最高水平，绝不会随着从业年限的拉长而自动水涨船高；但哪怕是经验极其丰富的老手，只要付出刻意求精的努力，其能力水平依然能继续向上突破”[(第 366 页)](http://www2.umassd.edu/swpi/DesignInCS/expertise.html)；而且“最有效的学习，需要一个目标明确且难度刚好匹配学习者当前水平的任务、及时且信息量充足的反馈，以及反复重来和修正错误的机会”（第 20–21 页）。《[实践中的认知：日常生活中的心智、数学与文化](http://www.amazon.com/exec/obidos/ASIN/0521357349)》（*Cognition in Practice*）一书对这一观点提供了非常耐人寻味的论证。
- **与其他程序员深入交流；大量阅读别人写的源码。** 这一点比你读任何教材、上任何培训班都要重要得多。
- 如果条件允许，不妨去**大学**读上四年本科（或者继续深造读个研究生）。一纸文凭能帮你敲开某些设置了学历门槛的工作大门，正规科班训练也能让你对该领域的底层理论有更深邃的理解；但如果你实在不喜欢学校体制，只要肯下苦功，你完全可以通过自学或在实战工作中攒下同等水准的历练。无论如何，光靠啃书本是绝对不够的。《新黑客词典》（*The New Hacker's Dictionary*）的作者埃里克·雷蒙德（Eric Raymond）说得好：==“计算机科学教育不可能把任何人直接培养成编程专家，正如光研究画笔和颜料不可能让任何人成为绘画大师一样。”== 我这辈子招过的最顶尖的程序员之一（Jamie Zawinski），最高学历就只有高中文凭；但他亲手写出了[XEmacs](http://www.xemacs.org)和早期[Mozilla/Netscape](http://www.mozilla.org)等一大批伟大的软件，拥有专门以他名字命名的[粉丝新闻组](http://groups.google.com/groups?q=alt.fan.jwz&meta=site%3Dgroups)，而且靠股票期权赚到了足够多的钱，直接在旧金山买下了一家属于自己的[传奇夜店（DNA Lounge）](http://en.wikipedia.org/wiki/DNA_Lounge)。
- **与其他程序员组队做项目。** 在某些项目里当团队里水平最高的程序员，在另一些项目里当团队里水平最菜的程序员。当你充当最强者时，你能锻炼自己领导项目的能力，并学会用技术愿景去激励队友；而当你甘当最弱者时，你能近距离偷师顶尖高手是如何思考和行事的，同时也会摸清楚高手们最讨厌干哪些脏活累活（因为他们会把那些活全都丢给你去干）。
- **接手维护别人留下的项目。** 去读懂一个完全由别人编写的程序。去亲身体会一下，当原作者早就离职不在场时，想要搞懂一套旧代码并修好里面的 Bug 需要付出怎样的代价。经受过这种毒打之后，你自然就会开始认真思考：我该如何设计自己的程序，才能让将来接盘维护我代码的后人少骂几句娘？
- **至少学会半打（六门以上）编程语言。** 其中应当包括：一门强调类抽象（Class abstraction）的语言（如 Java 或 C++），一门强调函数式抽象（Functional abstraction）的语言（如 Lisp、ML 或 Haskell），一门支持语法抽象（Syntactic abstraction）的语言（如 Lisp），一门支持声明式规约（Declarative specifications）的语言（如 Prolog 或 C++ 模板），以及一门强调并行计算（Parallelism）的语言（如 Clojure 或 Go）。
- **永远别忘了“计算机科学（Computer Science）”这个词里包含着“计算机（Computer）”二字。** 你必须对自己手里的计算机硬件有清晰的量级概念：知道你的电脑执行一条普通指令需要多长时间、从内存中读取一个字（Word）需要多长时间（分别在缓存命中和缓存未命中的情况下）、从磁盘顺序读取连续数据需要多长时间，以及磁头在磁盘上寻道跳转到新位置需要多长时间。（[标准答案见文末附表。](#answers)）
- **亲身参与一次语言标准化或规范制定的工作。** 它既可以是高大上的 ANSI C++ 标准委员会，也可以仅仅是参与决定你们团队内部的代码规范到底是用 2 个空格还是 4 个空格缩进。无论规模大小，你都会在唇枪舌剑中深刻体会到：别人到底看重一门语言的什么特性，他们的执念有多深，甚至能稍微理解一点他们为什么会有那么深的执念。
- **然后，拥有足够的明智与常识，以最快的速度从语言标准化的泥潭里抽身退出来。**

把上面这些要求通盘考虑一遍，你就会明白，单靠闷头啃书本究竟能走多远实在要打一个大大的问号。在我的第一个孩子出生之前，我把市面上所有教人怎么当父母的《育儿指南》全都买回来通读了一遍，结果孩子呱呱坠地那一刻，我依然觉得自己像个手足无措的菜鸟。30 个月后，当我的第二个孩子即将出生时，我有没有再把那堆育儿书翻出来复习一遍呢？压根没有。相反，我完全依靠自己带老大时攒下的实战经验，事实证明，这些亲身经历比专家们洋洋洒洒写下的几千页纸要管用得多，也让我心里踏实得多。

图灵奖得主、《人月神话》作者弗雷德·布鲁克斯（Fred Brooks）在他那篇著名的论文《[没有银弹](http://en.wikipedia.org/wiki/No_Silver_Bullet)》（*No Silver Bullet*）中，提出了一套发掘顶级软件设计师的三步走计划：

1. 尽早且系统化地识别出有潜力的顶尖设计师苗子。
2. 为这些好苗子配备专门的职业导师，负责其成长发展，并精心维护一份长期的职业成长档案。
3. 为成长中的设计师们创造大量相互切磋、彼此激发火花的交流机会。

这套方案隐含着一个前提假设：有些人天生就已经具备了成为伟大软件设计师的底层潜质，组织需要做的只是恰当地引导和栽培他们。[艾伦·佩利](http://www-pu.informatik.uni-tuebingen.de/users/klaeren/epigrams.html)曾用一句更凝练的话表达过同样的意思：“任何人都能被教会如何雕刻石头；但对于米开朗基罗来说，你反而得教他怎样才能停下来不去雕刻。伟大的程序员也是如此。”佩利的意思是，真正的大师体内都有某种超越后天训练的内在特质。可这股内在特质究竟是从哪儿来的呢？真的是娘胎里带来的天赋吗？还是他们在日复一日的勤勉苦练中修出来的？正如皮克斯动画《料理鼠王》（*Ratatouille*）里那位虚构的厨神古斯托（Auguste Gusteau）所言：“人人皆可下厨，唯无畏者方能成就伟大（Anyone can cook, but only the fearless can be great）。”在我看来，所谓的“无畏”，更像是**愿意把自己生命中极其庞大的一块光阴，毫无保留地奉献给枯燥的刻意练习**。不过，用“无畏（Fearless）”这个词来概括这种决绝的投入，倒也确实贴切。又或者，正如动画里那位苛刻的美食评论家安东·伊戈（Anton Ego）最后领悟到的那样：==“并非每个人都能成为伟大的艺术家，但伟大的艺术家可能来自任何不起眼的角落。”==

所以，尽管去书店买下那本 Java、Ruby、JavaScript 或 PHP 入门书吧，你多半能从里面学到一点有用的东西。但指望在 24 小时或 21 天之内改变你的人生，或者让你真正脱胎换骨成为一名专业的程序员，那是绝无可能的。那么，不妨换个目标：在接下来的 **24 个月**里咬紧牙关、脚踏实地持续精进如何？嗯，现在你才算是真正摸到门道了……

## 答案：底层硬件操作耗时表

在一台典型个人电脑（PC）上执行各类底层操作的大致耗时（注：此表即著名的“每个程序员都应知道的延迟数字 Latency Numbers Every Programmer Should Know”的原始出处）：

| 计算机底层操作 | 大致耗时 |
| :--- | ---: |
| 执行一条典型 CPU 指令（execute typical instruction） | $1/1,000,000,000$ 秒 = **1 纳秒 (ns)** |

## 附录一：第一门编程语言该选什么？

很多人写信问我，初学者入门第一门编程语言应该选哪一门。这个问题没有标准答案，但你可以参考以下几条原则：

- **借力你的朋友（Use your friends）。** 每当有人问我“我到底该用什么操作系统，Windows、Unix 还是 Mac？”时，我的回答通常是：“你的朋友们用什么，你就用什么。”能够随时向身边的朋友请教所带来的巨大便利，足以抵消掉不同操作系统或不同编程语言之间那点本身的优劣差异。此外，也请考虑一下你“未来的朋友”：如果你一直在这条路上走下去，你将融入怎样的程序员社区？你所选的这门语言，背后是一个生机勃勃、不断壮大的活跃社区，还是一个日渐凋零的小圈子？遇到难题时，有没有充足的书籍、网站和在线论坛能帮你找到答案？你喜欢那些论坛里交流的人吗？
- **保持简单（Keep it simple）。** 像 C++ 和 Java 这样的工业级语言，原本就是为了满足大型专业团队协同开发、并严苛压榨代码运行时性能而设计的。因此，这些语言里塞满了专门针对大型工程场景的复杂机制。而你眼下的核心任务是“学会如何编程”，你根本不需要背负那些繁琐的工程包袱。你真正需要的，是一门从设计之初就致力于让单个新手程序员轻松上手、容易记住的简洁语言。
- **在交互中玩耍（Play）。** 假如让你学弹钢琴，你更愿意用哪种方式来学：是正常的“交互模式”，你手指按下琴键的那一瞬间就能立刻听到对应的音符响起？还是“批处理模式（Batch mode）”，你必须摸黑把整首曲子从头到尾弹完，最后才能一次性听到刚才弹出来的录音？显而易见，实时反馈的交互模式让学钢琴变得容易得多，学编程也是完全一样的道理。请务必选择一门带有交互式解释器（REPL）的语言，并在交互模式中尽情探索。

综合以上几条标准，对于人生第一门编程语言，我的个人推荐是 **[Python](http://python.org)** 或 **[Scheme](http://www.schemers.org)**。另一个可选方案是 **JavaScript**，倒不是因为它为初学者设计得有多么完美无瑕，而是因为网上针对它的免费互动教程实在太丰富了，比如[可汗学院（Khan Academy）的在线编程教程](https://www.khanacademy.org/computing/cs/programming)。当然，每个人的具体情况不同，市面上还有其他很棒的选择。如果你的年龄还是个位数（十岁以下儿童），你或许会更喜欢 [Alice](http://alice.org)、[Squeak](http://www.squeak.org/) 或 [Blockly](https://blockly-demo.appspot.com/static/apps/index.html)（其实成年初学者也能在这些可视化编程工具里玩得很开心）。最关键的一点是：**赶紧选定一个，然后立刻动手开始写。**

## 附录二：推荐书籍与其他学习资源

还有很多人问我应该读哪些书、看哪些网站。我必须再三强调那句话：“光靠啃书本是绝对不够的”，但如果你需要一份高含金量的书单，我可以推荐以下几部经典：

- **Scheme：** 阿贝尔森与萨斯曼（Abelson & Sussman）合著的《[计算机程序的构造和解释](http://www.amazon.com/gp/product/0262011530)》（*Structure and Interpretation of Computer Programs*，简称 **SICP** / 紫皮书），很可能是世上最伟大的计算机科学导论教材。它真正把编程当成一种理解计算机科学本质的思维方式来传授。你可以在网上免费观看配套的[经典授课视频](http://www.swiss.ai.mit.edu/classes/6.001/abelson-sussman-lectures/)，也可以直接阅读[全书在线完整版](http://mitpress.mit.edu/sicp/full-text/book/book.html)。这本书颇具挑战性，可能会劝退一部分原本适合通过其他温和路径入门的初学者。
- **Scheme：** 费莱森（Felleisen）等人合著的《[程序设计方法](http://www.amazon.com/gp/product/0262062186)》（*How to Design Programs*，简称 **HtDP**），是关于“如何以优雅、实用的方式从头设计程序”的最佳入门著作之一。
- **Python：** 约翰·泽尔（John Zelle）所著的《[Python 编程：计算机科学导论](http://www.amazon.com/gp/product/1887902996)》（*Python Programming: An Intro to CS*），是一本用 Python 语言讲授计算机科学基础的优秀教材。
- **Python：** 在 [Python.org](http://python.org) 官网上可以找到许多非常实用的在线[初学者入门指南](http://wiki.python.org/moin/BeginnersGuide)。
- **Oz：** 范·罗伊与哈里迪（Van Roy & Haridi）合著的《[计算机编程的概念、技术与模型](http://www.amazon.com/gp/product/0262220695)》（*Concepts, Techniques, and Models of Computer Programming*，简称 **CTM**），被许多人誉为 SICP 的现代继承者。它带领读者纵览了编程世界里的所有核心大思想，涵盖的编程范式比 SICP 更加宽广，同时读起来或许也更加平易近人。全书使用的教学语言是 Oz，这门语言虽然名气不大，但非常适合作为理解其他各类编程语言底层机制的跳板。
