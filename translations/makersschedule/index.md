# 创造者的时间表，管理者的时间表

> 原文：[Maker's Schedule, Manager's Schedule](https://www.paulgraham.com/makersschedule.html) · 作者：Paul Graham（2009年7月） · [查看英文原版](./en.md)

![创造者的时间表，管理者的时间表](/images/makersschedule/makers-schedule.webp)

> “……光是脑子里惦记着今天有一场约会，有时候就足以毁掉一整天。”
>
> **查尔斯·狄更斯（Charles Dickens）**

程序员之所以如此痛恨开会，一个核心原因在于他们遵循的时间表类型与其他人截然不同：**开会这件事，对他们而言代价要高昂得多。**

世上存在两种截然不同的时间表，我把它们分别称为“**管理者的时间表（Manager's Schedule）**”和“**创造者的时间表（Maker's Schedule）**”。管理者的时间表是为老板和高管们准备的，它的具象化体现就是传统的日程预约本，把每一天整齐地切分成以“**一小时**”为单位的格子。如果某项任务确实需要，你也可以连续划出几个小时专门处理它；但在默认情况下，你每一个小时都在切换手头所做的事情。

当你以这种方式使用时间时，跟某人见个面开个会，纯粹只是一个日程排期上的实操问题：在你的日程表里找一个空闲的一小时格子，把对方填进去，这事就搞定了。

绝大多数掌握权力的人都运行在“管理者的时间表”上。那是一套发号施令的时间表。但在那些亲手创造事物的人（比如程序员和写作者）当中，普遍流行着另一种截然不同的时间使用方式。==他们通常需要以“至少半天”为基本单位来使用时间。你根本不可能以一小时为单位写出好文章或好代码，因为一小时甚至连热身进入状态都不够。==

当你运行在“创造者的时间表”上时，开会简直就是一场灭顶之灾。哪怕只有一场短短的会议，也能彻底炸毁整个下午，因为它把原本完整的一个下午硬生生劈成了两截，而每一截都短得不足以攻克任何真正有难度的硬骨头。更别提你脑子里还得时刻记着“待会儿要去开会”这档子事。对于遵循管理者时间表的人来说，这根本不算个事，因为每个整点本来就会有下一件事迎面撞上来，唯一的区别无非是下一件事具体是什么罢了。但当一个遵循创造者时间表的人今天有一场会时，他一整个半天都得提心吊胆地惦记着它。

==对于遵循创造者时间表的人来说，开一场会就像在程序运行中强行抛出了一个异常（Exception）：它不仅仅是让你从一项任务切换到另一项任务，更是强行打断并切换了你大脑运转的工作模式。==

我发现，哪怕只有一场会议，有时也足以波及并毁掉我的一整天。一场会通常会直接废掉至少半天时间，把原本完整的上午或下午切得支离破碎。但除此之外，它往往还会引发一种**连锁坍塌效应（Cascading effect）**：只要我知道今天下午会被一场会议切碎，我今天早上启动某个极具野心的硬核项目的意愿就会随之降低。我知道这听起来或许有些过于敏感矫情，但如果你也是一名创造者，不妨回想一下你自己的亲身感受：当你早上醒来，想到今天一整天都自由支配、没有任何一场预约或会议时，你的精神难道不会瞬间为之一振吗？反过来，这就意味着当你今天有会要开时，你的心气和情绪就会相应地低落下去。而那些真正有野心的硬核项目，根据定义，本来就逼近你脑力极限的边缘；士气上哪怕一丁点微小的折损，都足以将它们彻底扼杀在摇篮里。

这两种时间表各自独立运转时，都工作得非常好。真正的问题，出在当它们迎头相撞的时候。由于公司里绝大多数掌握大权的人都运行在管理者的时间表上，只要他们愿意，他们完全有权力强迫所有人都按照他们的频率共振。但那些真正聪明的管理者懂得克制自己，只要他们明白手下有一批人必须拥有整块不受打扰的长时段才能干出真活。

我们自己的处境则非常特殊。几乎所有投资人（包括我认识的所有风险投资家 VC）都运行在管理者的时间表上。但 [Y Combinator](http://ycombinator.com/) 却运行在创造者的时间表上。罗伯特·莫里斯（Rtm）、特雷弗·布莱克威尔（Trevor）和我之所以这样，是因为我们一辈子都是这么过来的；而杰西卡（Jessica Livingston）绝大部分时间也是如此，因为她的节奏已经和我们完全同步了。

如果未来出现越来越多像我们这样的公司，我一点也不会感到惊讶。我猜测，未来的创业者们或许越来越有底气去抗拒（或者至少推迟）把自己变成纯粹的管理者，就像几十年前的硅谷创业者们开始有底气拒绝脱下牛仔裤换上西装一样。

那么，既然我们运行在创造者的时间表上，我们究竟是怎么做到同时辅导这么多初创公司的呢？答案是：我们使用了一套在创造者时间表内部模拟管理者时间表的经典机制，也就是大学教授常用的**“固定答疑时间（Office Hours）”**。每周有好几次，我都会专门划出一整块时间，集中约见我们投资的创业者。这些时间块全部被安排在我**一天工作临近结束的末尾**，而且我自己写了一个预约排期程序，强制确保某一段答疑时间内的所有会面都紧凑地聚拢在一天工作日的最后时段。正因为这些会面全都发生在一天工作的尾声，它们就永远不会构成打断。（除非对方的下班时间刚好跟我一模一样，否则这场会大概率还是会打断他们的时间表；但既然是他们主动发起预约的，这笔账对他们来说想必是划算的。）在最繁忙的季节里，答疑时间有时会拉得很长，以至于挤压了我当天白天的创作时长，但它们**绝不会在中间拦腰斩断**我的工作。

回想上世纪 90 年代我们自己做初创公司（Viaweb）的时候，我还演化出过另一种切分一天的独门窍门。那时候我每天吃完晚饭就开始写代码，一直写到凌晨 3 点左右，因为在深夜里没有任何人能来打断我。然后我会一觉睡到上午 11 点左右，起床去公司一直干到晚饭前，专门处理那些被我统称为“商务杂事（Business stuff）”的活儿。当年我从未用这套概念去总结过它，但实际上，我等于把每一天拆成了两个完整的工作日：白天活在管理者的时间表里，深夜活在创造者的时间表里。

当你运行在管理者的时间表上时，你可以干一件创造者时间表上的人打死也不愿意干的事：你可以去开**“试探性会面（Speculative meetings）”**。你可以纯粹为了“认识一下彼此、混个脸熟”而跟某人约见一小时。既然你的日程表里刚好空着一个格子，为什么不去见见呢？没准聊着聊着就会发现双方未来能在某个地方互相帮衬一把。

硅谷（乃至全世界）的商务人士每天都在马不停蹄地开这种试探性会面。如果你运行在管理者的时间表上，这种会面几乎是零成本的。它们是如此司空见惯，以至于商务圈里诞生了一套专门用来发起这类会面的黑话，比如提议大家出来**“喝杯咖啡（Grab coffee）”**。

然而，如果你运行在创造者的时间表上，这种试探性的“喝杯咖啡”代价就惨重得可怕了。这让我们陷入了一种相当尴尬的两难境地：外界所有人都理所当然地以为，我们既然是投资人，肯定也像其他 VC 一样运行在管理者的时间表上。于是他们热情地把某个他们觉得我们“应该认识一下”的人引荐给我们，或者给我们发一封邮件提议出来“喝杯咖啡”。这时候摆在我们面前的只有两条路，而且两条都很糟糕：要么我们答应赴约，然后白白报废掉整整半天的创作工作；要么我们设法推脱不见，结果大概率得罪了对方。

直到最近，我们自己脑子里也没彻底想明白这种左右为难的根源究竟出在哪里。我们以前只是认命地以为，要么牺牲自己的工作日程，要么得罪人，二者必居其一。但现在既然我已经看清了背后的底层机制，或许还存在第三种选择：**写一篇文章，把这两种截然不同的时间表向世人解释清楚。** 也许终有一天，当“管理者时间表”与“创造者时间表”之间的天然冲突被越来越多人所理解时，它就不再是一个让人头疼的死结了。

==我们这些活在创造者时间表上的人，是愿意做出妥协的。我们很清楚自己不可能完全不开会。我们对那些活在管理者时间表上的人唯一的请求是：请理解一场会议让我们付出的真实代价。==
