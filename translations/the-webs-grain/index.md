# 顺应 Web 的纹理（The Web's Grain）

> **原著**：Frank Chimero（2015 年 2 月 18 日） · [阅读英文原版 (English Original)](./en.md) · [原文链接](https://frankchimero.com/blog/2015/the-webs-grain/)

*本文整理自我在 [2015 年 Webstock 大会](http://www.webstock.org.nz/15/)上的主题演讲，也是我此前探讨“如何为屏幕做原生设计”的长文《屏幕想要什么（What Screens Want）》的姊妹篇。*

---

## 一、整理我们的失望

能先给你放段声音听听吗？相信我，绝对值回票价。哦对了，听的时候留意一下你的胸口，你可能会感觉到一股暖流慢慢涌上来，就像一口威士忌下肚后火辣辣的余温。

好了，来听听看：

<audio controls style="width: 100%; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/dialup.mp3" type="audio/mpeg" />
  你的浏览器不支持音频播放。
</audio>

是不是特别带感？在做这个网页的过程中，这段刺耳的“叮铃哐啷”拨号声我翻来覆去听了不下三四十遍；虽然你看不见我现在的样子，但我此时正挂着一脸傻笑在敲这行字。如果你也和我一样是在上世纪 90 年代第一次触网的，你现在八成也在跟着笑。

没错了，这段声音就是当年 56K 调制解调器（Modem）拨号连上互联网时的音频握手信号。而它之所以能让你胸口发热，是因为那股带着点酸楚的怀旧感。我把那串刺耳的杂音，同我早年刚踏入互联网时的全部惊奇与魔力牢牢绑在了一起。要是在当年有人告诉我，接下来十几年我都能以“为互联网做东西”为生，那简直是我能听到的最棒的喜讯。

但世事总在变。在听到那串拨号音十五年后的今天，当我写下这些文字时，当年的着迷已经褪色了。发生在我身上的事，发生在每一个老手身上：最初的惊奇感，被日复一日的从业经验消磨殆尽了。

敬畏心散去了；时间带走了它。

---

法国哲学家加斯东·巴什拉（Gaston Bachelard）说过一句话：“我们始于赞叹，终于整理自己的失望。”

这话听着确实有点悲观（毕竟人家是法国哲学家嘛），但放在眼下的科技行业里，简直字字扎心。想想看我们这群人给这个世界增加了多少沉重的负担：贪婪吞噬人类注意力的设备与服务、非但没有消除不平等反而加剧了贫富分化的新型商业模式、夸夸其谈的技术官僚，更别提如今每个人头顶上那片无处可逃的监控风暴了。

任何一个还有点自知之明的科技从业者，怎么可能不开始“整理自己的失望”？事情已经发展到了我身边好几位同行开始半开玩笑地盘算转行干点别的地步。这可不是什么好兆头：你肯定希望那些有才华、有良知的人留在行业里，而不是被榨干热情后带着挫败、疲惫与自我怀疑黯然离场。

我离这个行业的核心越近，就越觉得困惑和窒息。那个我曾经无比熟悉的互联网，触角伸得越来越广，可我却越来越看不懂它了。所以在去年，我没有选择继续钻牛角尖、抱怨或者躺平无力，而是主动去寻找一种不同的视角。我想把那个已经膨胀得庞大无比的东西，重新变小。这件事迫在眉睫：我必须找到一种办法，在最地基的层面上重新与我的手艺建立连结；否则，我也得去物色第二职业了。

## 二、初心：看山仍是山，看水仍是水

在佛教禅宗里，有一个概念叫“初心（Beginner's Mind，即初学者之心）”。如果你做过任何形式的冥想引导，应该对这个词不陌生。它指的是一种敞开、热切的心态：放下沉重的成见与套路，换一种全新的眼光去审视熟悉的日常，从而让一门手艺重新焕发生机。当时“做网页”这件事已经让我感到不堪重负，而“初心”恰恰是我最需要的解药。

几乎所有关于“初心”的探讨，最终都会引向同一则著名的禅宗公案（中国禅宗青原惟信禅师的“见山三阶段”）：

> 老僧三十年前未参禅时，见山是山，见水是水。及至后来，亲见知识，有个入处，见山不是山，见水不是水。而今得个休歇处，依前见山只是山，见水只是水。

这则公案到底在讲什么道理？我的理解是：==我们最终都会走过那个“误以为深刻来自于复杂化”的幼稚阶段。事实根本不是那样。事物本身就拥有足够的深度与价值。== 想要获得洞见，不需要套用那些花里胡哨的隐喻或类比，只需要你愿意静下心来，倾听事物自己替自己说话，哪怕它说出来的话违背了行业里公认的教条。

今天，我就想试着做一回倾听者。

## 三、响应式设计最底层的视觉死结

当你把一个网站就当作“网站本身”去端详时，你能看到什么？其实能看到很多东西，但让我们先把一切剥离到最核心的骨架。在接下来的拆解里，如果我说了太多显而易见的大白话，还请多包涵。我的目的就是如实描述和记录那些摆在明面上的基本事实。还记得吧？看水只是水。

下面是一张纯粹到极点的素颜网页：没有任何 CSS 样式，只有纯 HTML 标签，全都是浏览器的出厂默认设置。

![纯 HTML 默认标记渲染出的网页](/images/the-webs-grain/code1.webp)

观察这张页面，你注意到的第一件事就是：**它是流动的（Fluid）**。它会自动适应浏览器视口（Viewport）的宽度，把画面填满。我们还不完全能叫它“响应式网页（Responsive）”，因为严格意义上的响应式网站需要用到 CSS 媒体查询（Media Queries）；但这个纯素颜页面和响应式网站一样，对视口尺寸没有任何死板的执念。不管你把窗口拉成什么尺寸，它都能稳稳当当地正常显示。

<video controls preload="none" loop poster="/images/the-webs-grain/fluidwebpage1-poster.webp" style="width: 100%; border-radius: 8px; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/fluidwebpage1.mp4" type="video/mp4" />
</video>

页面的这种流动性，自然引出了你注意到的第二件事：**网页天生是纵向延伸的（Vertical）**。

<video controls preload="none" loop poster="/images/the-webs-grain/fluidwebpage2-poster.webp" style="width: 100%; border-radius: 8px; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/fluidwebpage2.mp4" type="video/mp4" />
</video>

好吧，这简直是废话中的废话，但让我们把这层窗户纸捅破，仔细琢磨一下。

在默认状态下，网页元素会像千层蛋糕一样自上而下垂直堆叠。这非常合乎情理：垂直堆叠在跨越各种稀奇古怪的屏幕尺寸时最容易适配，因为你根本不需要去操心横向空间多了还是少了的排版难题，直接让每个元素占满 100% 宽度就行了。这套逻辑对“移动优先（Mobile First）”等设计方法尤为顺手，因为窄小的手机屏幕本来就放不下左右并排的元素。靠着垂直堆叠，无论屏幕大小如何变化，设计都能保持极高的一致性。

可是，总不能天底下所有网站都做成一摞竖着码放的砖头吧？如果你非要把两个元素左右并排放在一起，会发生什么？

这就直接撞上了**响应式设计最核心的视觉难题**。它是响应式排版的老祖宗级痛点，是扎在每个设计师肋骨上的一根老刺，但不知为何，我以前竟然从没见过有人把它白纸黑字地总结出来。

让我们回到刚才那个纯 HTML 页面，稍微加几行 CSS，让图片和文字左右并排各占一半宽度，并随着视口宽度的变化按比例缩放：

![给纯 HTML 加上几行 CSS 让图片与文字并排显示](/images/the-webs-grain/code2.webp)

好，瞪大眼睛看仔细了：

<video controls preload="none" loop poster="/images/the-webs-grain/fluidwebpage3-poster.webp" style="width: 100%; border-radius: 8px; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/fluidwebpage3.mp4" type="video/mp4" />
</video>

我来解释一下刚才发生了什么：**当我把浏览器窗口拉宽时，图片随着变宽而变得越来越“高”，因为图片的宽高比是固定的；但旁边的文字段落却随着变宽而变得越来越“矮”，因为文字流没有固定的宽高比！**

如果你亲手设计过响应式网站，这就是你一切悲伤的源泉。这是你眼泪的喷泉，是你痛苦的苦海。如果你相信有来世，这就是地狱里专门用火烤设计师脚底板的那一层。

你一定听人说过：“当响应式排版拉到某个宽度开始显得怪模怪样时，就在那里加一个断点（Breakpoint）吧！”==看清楚了，上面这个图文高度反向变化的死结，就是让排版每次拉着拉着就变得怪模怪样的罪魁祸首，无一例外。== 但这个矛盾是植根于数学规律里的，既无法回避，也不可能被彻底消灭；因此我们唯一的选择，就是承认它是网页这种媒介与生俱来的内生属性，并设计出顺应它的管理策略。

## 四、“骑自行车的熊” vs 顺应 Web 的纹理

我们这门手艺里绝大多数真正经得起时间检验的技法，其实都顺应了 Web 从诞生第一天起就具备的天然秉性。答案一直就摆在我们眼皮子底下，就写在最原始的网页里；我们每背离它的天性一步，造出来的作品就会脆弱一分。

当你非要逆着 Web 的天然脾气硬来时，做出来的东西会是什么样？嗯，大概率长这样：

![一只真正骑在自行车上的熊](/images/the-webs-grain/bicyclebear.webp)

你会造出我称之为**“狗熊骑单车式网站（Bicycle bear websites）”**的东西。为什么这么叫？因为我看到这类网站时的第一反应，跟看到马戏团里狗熊骑自行车时的反应一模一样。

我会说：“听着老兄，你能教会一头大狗熊骑自行车，确实非常了不起，看着既新奇又抓人眼球。但你有没有想过，这其实有点残忍？因为骑自行车压根就不是狗熊该干的事啊。而且老兄，咱们说句实在话，那头熊这辈子也不可能真正把自行车骑利索的。”

每次我看到网上那些极尽炫技之能事的酷炫网站时，心里冒出来的就是这句话：“你能用代码做出这种效果确实很牛，但这真的不是一个网页该干的事。”举个活生生的例子，请欣赏当年苹果官网为垃圾桶 Mac Pro 做的宣传网页：

<video controls preload="none" loop poster="/images/the-webs-grain/macprosite-poster.webp" style="width: 100%; border-radius: 8px; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/macprosite.mp4" type="video/mp4" />
</video>

看这个网站的体验跟看狗熊骑单车如出一辙：前两秒全是惊叹和欢呼，紧接着车把就开始失控乱晃，然后你惊恐地发现它正朝你脸上直冲过来。

这到底是个什么怪物？为什么浏览个网页搞得像在手动对接国际空间站？为什么我滚不动页面了？为什么我花大价钱买的顶配笔记本电脑开始掉帧卡顿了？等等，那是什么声音？我电脑风扇起飞的呼啸声吗？（关于如何在网页中克制、优雅地使用动效，也可参阅站内[《CSS 动画缓动曲线指南》](/posts/css-easing/)。）

苹果为了追求极致酷炫，造出了一个极其脆弱、故作高深、对谁都不好使的畸形网页。我相信你脑子里肯定也能立刻蹦出好几个类似的例子：那些笨重不堪、处处跟 Web 的天然倾向拧着干的网站。回到前面那则禅宗公案：如果说“看山是山，看水是水”，那么这些网站就是拼命想要标新立异，结果却沦为了逆流而上、推石上山的苦役。

---

我坚信**每一种材料都有它自己的“纹理（Grain）”，Web 也不例外。** 木匠刨木头要顺着木纹刨，逆着木纹就会起毛刺、崩裂。但“Web 也有纹理和脾气”这个观点，却直接打了我们对现代科技一贯期待的脸。长久以来，人们总把互联网描绘成一块毫无限制、想捏成什么样就能捏成什么样的万能橡皮泥；我们总指望技术能帮我们消灭一切限制，而不是给我们制造新的限制。然而，尽管口号喊得震天响，我们在实战中最终收敛出来的设计解法，却呈现出惊人的一致性：

![Commercial Type 字体展示网站](/images/the-webs-grain/pattern-color.webp)
*Commercial Type 的字体展示网站*

我们大量使用**纯色块与简洁的渐变**，因为它们体积轻量、直接用几行 CSS 就能画出来，而且面对未知宽高比的容器时可以任意拉伸而不失真。

![《设计的形状》书籍官网](/images/the-webs-grain/pattern-sod.webp)
*《The Shape of Design》书籍官网*

网站普遍采用**横向通栏的大色带（Horizontal stripes）**来切分内容区块，这正是顺应了我前面提到的“网页纵向堆叠天性”。

![Dropmark 界面](/images/the-webs-grain/pattern-interface.webp)
*Dropmark 官网*

我们直接把**排版文字当作交互界面（Text as interface）**，因为软件底层那些微妙却关键的抽象概念差异，单靠画图标是很难准确传达的。

![Obvious Ventures 官网](/images/the-webs-grain/pattern-photo.webp)
*Obvious Ventures 官网*

我们喜欢拿**讲究氛围感、虚化或加了色彩滤镜的照片当背景大图**，因为我们根本无法预知它在不同宽窄的屏幕上会被裁切成什么样；而在背景图正中央叠加上大号标题文字，不仅是因为每个甲方爸爸都要求“图片要大、字也要大”，更因为这种“字叠图”的做法巧妙地绕开了我前面演示过的“图文并排时高度反向缩放”的死结！

![MailChimp 官网](/images/the-webs-grain/pattern-tableau.webp)
*MailChimp 官网*

我们热衷于拍摄**带着桌面小道具的实景产品照**，因为纯软件实在太抽象、摸不着看不见，把它放进一台摆在真实办公桌上的手机或电脑屏幕里，才能让用户觉得它是一件实打实的商品。

![DBLG 官网](/images/the-webs-grain/pattern-mosiac.webp)
*DBLG 官网*

我们还普遍采用**马赛克网格拼贴（Mosaics）**，因为每个页面都要承载五花八门的海量元素，我们需要一种结构化的方式来整齐陈列这种多样性。

---

你看，Web 的物理特性正在倒逼我们做出这些选择。而这完全没问题！许多网站之所以长着相似的骨架，是因为我们手里用的是同一种建筑材料。==这种跨越站点的共性沉淀出了行业最佳实践；它们证明了设计师们摸准了同一种媒介的脉搏，顺应了材料的纹理，绝不该被浅薄地嘲笑为“千篇一律的视觉同质化”。==

这是一个很好的起点，但也仅仅是个起点。前面展示的那些顺应天性的简单网页，能不能在具体页面排版之外给我们提供更宏大的思考启发？把问题问得更尖锐一点：**如果我们不再把 Web 当作一张任由我们在上面涂抹作画的空白画布，而是把它当作一种用来“搭建（Build with）”的建筑材料，会发生什么？**

结果，我竟然从一位同样决定走出画布限制的画家身上，找到了这个问题的答案。让我们先来上一节简短的艺术史课，好吗？

---

## 五、大卫·霍克尼的拼贴摄影：控制 vs 发现

<video controls preload="none" poster="/images/the-webs-grain/hockneyposter.webp" style="width: 100%; border-radius: 8px; margin: 12px 0;">
  <source src="https://frankchimero.com/images/posts/webs-grain/hockneyclip2.mp4" type="video/mp4" />
</video>

来认识一下大卫·霍克尼（David Hockney）：艺术家、画家，也是一位对传统摄影充满怀疑的摄影师。在 20 世纪 80 年代初，他暂时放下了画笔，一头扎进了他在视频里提到的“拼贴摄影（Photographic joiners）”实验。这些作品是对“时间与空间”的视觉探索。听起来好像很玄乎，但只要你亲眼看上一眼，瞬间就能明白我在说什么。它们看着有点像立体主义画作，但读懂它们要直观得多。我给你挑几幅看看。

正如霍克尼在视频里所说，他最早是用宝丽来（Polaroid）拍立得相纸开启这个项目的。你可以看到下面这幅作品是由一张张宝丽来照片像瓷砖一样拼贴而成的，因为任何单张照片都无法装下眼前的整个场景。

![大卫·霍克尼：《诺亚与比尔·布兰特及自画像》，1982](/images/the-webs-grain/hockney1.webp)
*《诺亚与比尔·布兰特及自画像（尽管他们当时正看着这幅作品被拍摄出来）》，大卫·霍克尼，1982 年*

在这幅作品内部，霍克尼利用“视觉冗余”在静态画面里拍出了动态的时间感。你数数看里面有几只手？那个男人有几个脑袋？把局部放大看，画面里有两张脸，但你绝不会觉得这是一个长着两个脑袋的怪物；你会自然而然地读懂，这是目光在同一张脸上停留的两次注视，是同一个人在不同时间切片下的两个侧面。

![《诺亚与比尔·布兰特》局部放大](/images/the-webs-grain/hockney2.webp)

这种过渡是如此自然无缝，要不是我特意提醒，你甚至根本不会去数画面里有几张脸。你一眼就能看懂，因为**人类真实的眼睛本来就是这么看世界的**：人眼的清晰对焦范围其实非常窄，全靠眼球不断跳动扫视，再由大脑把这一个个局部碎片实时拼接成一幅完整的画面。

再来看另一幅更进阶的作品。这是我个人最喜欢的一幅，因为它的手法极其克制高效，就像一格格连环画一样：

![大卫·霍克尼：《比利·怀尔德点雪茄》，1982](/images/the-webs-grain/hockney3.webp)
*《比利·怀尔德点雪茄》，大卫·霍克尼，1982 年*

看出变化了吗？霍克尼不再使用带白边的宝丽来相纸了。死板的网格消失了，取而代之的是相互叠压、没有白框限制的普通冲印照片。没有裁切，没有花招，仅仅用了六张照片，霍克尼就活灵活现地还原了一整套点烟动作与空间层次。

如果把这套无边框拼贴手法放大到几十上百张照片，会长成什么样？霍克尼自己也问了同样的问题：

![大卫·霍克尼：《拼字游戏》，1982](/images/the-webs-grain/hockney4.webp)
*《拼字游戏（The Scrabble Game）》，大卫·霍克尼，1982 年*

这幅作品叫《拼字游戏》，在我看来，它是霍克尼这一创作时期的巅峰杰作。整幅画面热闹非凡：到处是表情各异的脸，到处是正在移动的手。每一张局部照片里的棋盘状态都处于不同的时间点上，你甚至能顺着照片推演出他们一步步出牌的先后顺序。（顺便吐槽一句，每次看这幅画我都急得抓耳挠腮：他手里的字母牌明明就能拼出 `Liqueur` 这个词，他怎么就是看不见呢！）

好，现在你看出来这其中的演进脉络了吗？把我们看的第一幅宝丽来网格拼贴画，和这幅《拼字游戏》并排放在一起对比一下：

![《拼字游戏》与早期宝丽来网格拼贴作品对比](/images/the-webs-grain/hockney5.webp)

霍克尼刚起步时，受制于宝丽来相纸自带的方框白边，只能按网格对齐排列，最后拼出来的成品依然是一个规规矩矩的大矩形。而当他换用普通无边胶片冲洗照片后，他就可以顺应场景本身的时间与空间走势，让照片自由叠压延展，最终生长成任何需要的形状。没有任何人会预先画好这样一个锯齿状的怪异外框再去往里填照片；你所看到的这个不规则外轮廓，纯粹是由他抓拍到的内部内容自然生长、向外推挤出来的结果。

从本质上说，霍克尼彻底抛弃了“二维视觉作品必须存在并受限于一个固定矩形画框”的传统执念。相反，一张张独立的局部小照片彼此叠压、组装，直到共同生长为一幅完整的图景。单拿出来看，每一张小照片都平平无奇；但当它们组合在一起时……等等，这套逻辑听起来是不是有点耳熟？

好吧，对不起，我给你下了个套，我们绕了一大圈又回到了原点。我们其实一直都在聊响应式网页设计。让我们来做个直观的类比：

![《蒙娜丽莎》与霍克尼《拼字游戏》对比](/images/the-webs-grain/hockney6.webp)

左边是达·芬奇的《蒙娜丽莎》。虽然拿它举例有点俗套，但有什么关系呢？对我来说，这幅古典油画就像是为**印刷纸张（Print）**做设计；而右边的《拼字游戏》，这种由局部碎片组装生长出来的形态，才真正神似为**屏幕（Screen）**做设计。你看出来了吗？**左边是“控制（Control）”，右边是“发现（Discovery）”；左边是“整齐划一（Uniformity）”，右边是“多元共生（Multiplicity）”。**

面对《蒙娜丽莎》，我们拥有固定不变、四平八稳的画框边界，可以在动笔前进行高度确定、分毫不差的精密规划与控制。我们之所以顶礼膜拜这幅名画，正是折服于画家在方寸画框内展现出的极致控制力。

而面对霍克尼的拼贴画，我们领略到的是一种截然不同的美。它是一个**比例未知、没有固定边界的平面，由来自不同视角的独立、微小且多变的局部元素组装而成，最终交织成一个可读的整体，记录下流动的瞬间。**

*这不就是网页设计吗！* 来，我把刚才那句话原封不动地再念一遍，但这一次，请你在脑子里想的是“网页设计”而不是霍克尼的照片：

> ==一个比例未知、没有固定边界的平面，由来自不同视角的独立、微小且多变的局部元素组装而成，最终交织成一个可读的整体，记录下流动的瞬间。==

用这句话来概括交互与网页设计面临的视觉挑战，是不是精准得让人起鸡皮疙瘩？

---

## 六、无边界性（Edgelessness）：别再先画框了！

2013 年 11 月，我在题为《屏幕想要什么》的演讲中，曾试图回答“什么叫为屏幕做原生设计”。当时我给出的答案是一个词：**流变（Flux）**，即事物随时间与交互而改变形态的能力。这种流变既可以是炫目的动画，也可以朴素到只是一张电子表格点击表头后自动重新排序。这是死板的纸张永远做不到的事。因此，为屏幕做设计，本质上就是管理随时间发生的变化，并用清晰、易懂、有力的方式把它表达出来。

而今天，在盯着大卫·霍克尼的拼贴画看了太久之后，我要往这份清单里加上屏幕的第二种原生天性：**无边界性（Edgelessness）**。

只要你留心观察，“没有固定边界”的特质渗透在 Web 的每一个层级里：

![互联网拓扑图](/images/the-webs-grain/graph.webp)
*来自 OPTE 项目的互联网局部拓扑图*

首先，**Web 的底层拓扑结构是无边界的**：它由无数个独立的网页通过超链接（Hyperlinks）彼此串联而成，因此它的网络结构可以向四面八方无限分叉生长下去。

![无限滚动的画布](/images/the-webs-grain/infinitecanvas.webp)

其次，**承载 Web 的屏幕视口是无边界的**：屏幕提供了一块可以向任意方向无限滚动的画布。天哪，我们平时是多么习以为常地把“一块小小的屏幕竟然能装下比它物理面积大上百倍的内容”当成了理所当然的事！

![安卓设备屏幕尺寸碎片化光谱](/images/the-webs-grain/devicesizes.webp)
*OpenSignal 统计的 Android 设备屏幕尺寸碎片化光谱图（而且这还是 2012 年的数据）*

再者，**终端设备的尺寸光谱是无边界的**：上面这张图展示的仅仅是安卓阵营设备的屏幕尺寸分布。面对这样一个尺寸连续渐变、相邻设备之间只有几毫米微小差异的连续光谱，你怎么可能划得出几道泾渭分明的尺寸边界？

![倒塌的部门围墙](/images/the-webs-grain/edges.webp)

最后，也是我个人觉得最耐人寻味的一点：**无边界性意味着打造 Web 产品的各个专业工种之间的边界正在消融。** 我访谈过的每一位曾在大客户那里主导过大型响应式改版项目的同行都告诉我，响应式设计流程会彻底颠覆公司原有的工作流、交付预期与团队文化。

说白了，Web 本身的无边界性，一锤子砸碎了公司内部人为砌起来的部门高墙。由于产品里的所有环节都高度咬合联动，再也没有人能画地为牢、只管自己那一亩三分地了（比如视觉设计师画完固定尺寸的 PSD 扔给前端切图就万事大吉的时代彻底结束了）。围墙倒塌之后，我们所有人唯一的选择，就是学会在各个工种交汇的模糊地带里紧密协作。

---

让我们看看这种“无边界性”应该如何改变我们日常动手设计的方式。假设你现在要启动一个新网站项目，准备在纸上画点草图。你下笔的第一步会画什么？

你十有八九会**先画一个代表浏览器窗口的方框**：

![先画一个方框](/images/the-webs-grain/box1.webp)

然后，你再往这个方框里塞入网页的各个内容元素：

![往方框里填内容元素](/images/the-webs-grain/box2.webp)

哎呀，坏菜了。

还记得霍克尼的拼贴画吗？**在我们搞清楚里面要放什么内容之前，我们正在创造的这个东西到底需要多大尺寸、什么长宽比，根本就是未知的！** 因此，正确的做法应该是先把核心内容元素的组合关系编排好，然后再去给它们匹配合适的容器空间，而不是反过来先画一个死框框再去硬塞。==我们应该先画内容，最后再把框套上去！== 让我给你看个绝佳的实战案例。

下面这组草图来自丹麦设计师 [Kasper Laigaard](http://kasperlaigaard.com/?page_id=1078) 的作品集。它完美诠释了什么叫“在搞清楚里面装什么之前，绝不先画框”。在这组草图里，他正在为创意机构 Hello Monday 的官网改版构思不同的“内容组合块（Content lock-ups）”。这几张草图把这套思想解释得比我用任何语言描述都要透彻：

![Kasper Laigaard 为 Hello Monday 绘制的内容组合块草图](/images/the-webs-grain/laigaard.webp)
*Kasper Laigaard 为 Hello Monday 构思的内容组合块（Content lock-ups）草图*

看明白了吗？就像霍克尼拼接照片一样，我们也是先创造出一个个内聚的“元素组合体（Assemblages of elements）”，然后再把它们安置到不同尺寸的视口空间里去。

这种“自内向外组装生长（Assembling）”的工作方式，其实跟我们目前在响应式设计里常用的一整套行业术语是拧着的。我们平时嘴里说的术语（比如“断点 Breakpoint”、“拆解 Breakdown”），听起来好像我们是在设计一套“当屏幕变小时，页面如何一步步坍塌碎裂”的机制；但实际上，**我们真正应该聚焦设计的，是元素如何像积木一样一步步“向上生长组合（Build up）”！** 而这个理念，就像我们创造的网页布局一样，还可以向外延伸到更广阔的现实世界里。

---

## 七、走向优雅克制的技术（A Technology of Grace）

![从聚合走向发散的圆点动画](/images/the-webs-grain/dots.webp)

我们常常一厢情愿地以为，为互联网做产品是一个不断“化繁为简、万物归一”的收敛过程：什么全能中台、一站式仪表盘、超级控制中心，全都是技术人想要把一切收拢到一起的甜美幻梦。但现实中，技术演化的天然趋势偏偏是朝着多选项、多分支的**发散（Divergence）**狂奔而去的。我们往世界里堆叠了越来越多的工具与技术，每一个新工具都在极其细微的差异点上做文章。很显然，指望技术自动收敛和简化是不切实际的伪目标。相反，**我们真正应该追求的目标是“清晰（Clarity）”。** 你无法堵住或缩减技术奔涌而出的洪流，但你可以通过恰当的框架（Framing）与清晰的表达，把这股洪流引导向积极健康的河道（详见[《多元思维模型大全》](/translations/mental-models/)）。

技术永远只在做加法；它从来不是“有了这个，就淘汰了那个（This or that）”，它永远是“既要这个，又要那个（This *and* that）”。

举个我自己日常生活里的小例子：推特（Twitter）并没有取代脸书（Facebook）；iPad 并没有取代我的手机；我的手机也没有取代客厅里的电视。结果现在每天晚上的画面是：我捧着 iPad 刷 YouTube 视频，随手把视频投屏到电视机上播放，同时手里还攥着手机刷推特和脸书。我身边围绕着一整个由数码设备组成的“小星座”。但我一直在心底追问自己：我手里到底还能同时抛接多少个球？这种杂耍般的日子我还能撑多久？

面对这种信息与设备过载，科技行业给出的解药往往是更多的技术：上推荐算法、上自动化脚本、上各种微型程序和过滤规则，去替我们筛选从互联网排污口里喷涌而出的信息洪流。哪怕这些技术方案的初衷可能是善意的，但它们最终无一例外都变成了新的控制节点与权力寻租点。

==妄图用更多的技术去解决由技术泛滥本身制造出来的问题，就像想用青草去擦掉衣服上的草渍一样徒劳。== 堆砌更多的技术，只会成倍放大原本由技术过剩引发的恶果。这就把我们逼到了那个最紧迫的终极追问面前：技术的触角到底还要往外疯长到什么地步？它究竟在什么时候会彻底越过人类身心舒适的底线？

---

我们正在亲手建造一个个没有边界、不断向外发散膨胀的数字环境。新东西在混乱中被不断塞进来，一旦侥幸成功，就会进一步向四面八方疯狂扩张，直到撑破极限、坍塌重组。这大概就是为什么“响应式设计”会让我们觉得如此切中时代脉搏、却又如此令人抓狂和充满争议：因为响应式设计的内在张力，恰恰是整个现代技术扩张模式的缩影。

我们所建造的一切，都受制于其内部无法调和的底层矛盾。在响应式设计里，这个底层矛盾是我前面演示过的“图片与文字缩放高度相反”的死结；在更宏大的社会舞台上，是资本与劳工的博弈，或是集体管控与无政府个人主义的拉锯；而在现代科技领域，我认为一切矛盾最终都归结为**“便利性（Convenience）背后的权力博弈”**。

为了创造出便利，尤其是科技公司最爱兜售的那种“全自动、无感化的便利”，就必须有另一个人或算法在幕后替我们把选择做好了。换句话说：**你需要亲手操心的事越少，你手里的决定权和话语权也就越少。**

在一定限度之内，拿一部分自主权去换取省心省力是一笔很划算的买卖：毕竟谁愿意每天自己拿算盘珠子核对账本，或者非得亲自打电话去餐馆报菜名点外卖呢？但如果顺着这条路走得太远，**便利就会变成一座特洛伊木马。** 我们交出了太多的控制权，最终对自己再也无法驾驭的系统产生了重度依赖。那些当初拍着胸脯承诺“让流程更便捷、让关系更亲密”的平台，转身就以新型中间商的姿态死死卡在了每一次交易与连接的正中间。到头来，我们只能祈祷那些掌握着重塑我们生活习惯大权的科技巨头能大发慈悲。然而看看我在文章开头提到的那些行业乱象吧，坐在那个位置上的人，远没有我们期望的那么有责任感和同理心。在盲目追求极致便利的路上，我们已经亲手为肆无忌惮的操控敞开了大门。

---

你可以说，我们当下的技术生态已经过度扩张、摊得太散，开始显得怪模怪样、让人浑身不自在了。值得庆幸的是，我们可以像处理响应式排版一样来应对这场技术的过度膨胀：我们可以主动划下一道断点（Breakpoint），为我们造出来的这堆技术重新设定一个重组收敛的锚点。我们可以重新审视该如何挪动、调整和裁剪手头的工具碎片，让它们重新退回到服务于我们真实初心的轨道上来。而对于我们这群亲手制造技术的设计师与开发者来说，这份重塑的责任与力量更是成倍放大的。

但请记住，**解药绝不是又一个新开发出来的技术工具，而是一次清醒的意志决断（An explicit act of will）**。它取决于每一个个体主动选择改变自己的日常行为：选择使用什么工具、在哪里倾注心血、采纳什么、又对什么给予宝贵的注意力。它不过是朴素的“正念与觉察（Mindfulness）”，恰恰是那些贪婪索取注意力的现代科技最怕我们拥有的东西。而这一切，都始于向自己发出两个简单的提问：**技术在你的生命里究竟扮演着什么角色？你内心深处真正渴望从技术那里得到什么？**

至于我自己的答案？我不再奢求技术能赐予我内心的平静、安宁、轻松、魔力或任何它根本给不了的东西了；我已经彻底放下了那些空洞的许诺。我的愿望非常简单：**我渴望一种优雅得体的技术（A technology of grace），一种安守本分、恰如其分地活在自己角色里的技术。**

我们怎么才能知道自己终于抵达了那个理想境界呢？我想，到那时，当我们审视自己亲手搭建的数字作品，看到四周生硬的边界自然消融、画面看似可以向远方无限延展下去时，我们心里涌起的将不再是失控的焦虑，而是由衷的欢喜与从容。
