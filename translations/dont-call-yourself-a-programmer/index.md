# 别自称“程序员”，以及其他给年轻工程师的职业忠告

> 原文：[Don't Call Yourself A Programmer, And Other Career Advice](https://www.kalzumeus.com/2011/10/28/dont-call-yourself-a-programmer/) · 作者：Patrick McKenzie（patio11，2011 年 10 月 28 日） · [查看英文原版](./en.md)

如果让我给大学里的所有工科专业硬性增加一门必修课，我绝不会选编译原理、逻辑门电路或者时间复杂度分析，而是会开一门**《行业残酷真相导论（Realities Of Your Industry 101）》**。正因为学校里从来不教这些东西，无数年轻工程师在步入社会后才会吃那么多根本没必要吃的苦头。

这篇文章希望成为你开启工程师职业生涯的那份 `README.txt`（自述指南）。写它的目的很简单：补上学校教育里关于“真实商业世界究竟如何运转”的那块巨大空白，让你活得更痛快、更明白一些。我自己从一个“脑子还算灵光、但极度缺乏自信、商业实战常识为零的年轻工程师”起步，足足跌跌撞撞摸索了十年、栽了无数个跟头，才悟出下面这些道理。你不必把它奉为金科玉律，但它至少能告诉你许多大学就业指导中心永远不会告诉你的真话。

## 1. 90% 的编程工作，都是在写企业内部的业务软件

经济学第一课告诉我们：任何事物（包括你在内）的价格，都取决于供求关系。咱们先来看看需求端。

这世上绝大多数软件，既不是装在包装盒里售卖的套装软件，也不是挂在互联网上任人访问的明星网站，更不是你在 App Store 里随手下载的手机应用。**绝大多数软件，都是隐藏在各大公司内部、极其枯燥乏味的一次性业务系统（Line of Business software），它们在看不见的地方托起了全球经济的每一个角落。** 它们负责追踪差旅报销、优化物流运费、辅助财务部门编制预算报表、协助设计新款零件、给保险保单精算定价、或者把可疑订单标记出来交给反欺诈部门人工审核。

==软件存在的唯一意义，就是解决商业问题。== 哪怕一套软件枯燥到让人灵魂出窍、技术复杂度低到令人发指，只要它能解决商业问题，它就是好软件。

举个最简单的例子：假设你为一家拥有 2,000 名员工的公司写了一套内部差旅费报销表单系统。跟过去填纸质报销单相比，这套系统每年能帮全公司节省 5,000 个工时；按员工综合人力成本每小时 50 美元计算，**它每年就能实打实地帮公司省下 25 万美元**。在公司管理层眼里，这套报销表单是不是全世界最简陋的“增删改查（CRUD）”程序，根本就无关紧要；唯一要紧的，是它要么帮公司省下了真金白银的成本，要么帮公司赚到了实实在在的额外收入。

当然，世上确实有一小部分公司专门开发直接面向终端用户的软件（也就是大多数人一提到“软件”脑海里浮现的那些知名产品）。但除非你刻意朝着那个方向去规划和努力，否则你大概率不会进入这类公司工作。而且就算你真的进了这类明星科技公司，里面也有相当大一部分工程师每天写的根本不是面向外部用户的产品，而是支撑公司运转的内部业务系统。

## 2. 公司雇工程师是为了创造商业价值，而不是为了写代码

诚然，企业里无时无刻不在因为非理性冲动和办公室政治而做蠢事（后文会细聊），但从大方向上看，所有商业组织的行为最终都会收敛到两件事上：**增加营收（Increase revenue）**，或者**削减成本（Reduce costs）**。

在一家运转良好的公司里，地位、奖金与话语权，通常会奖励给那些成功把这两件事的功劳揽到自己名下的人（这可以包括亲手做成这些事，但并不总是互为充要条件）。那个拍板决定再招一名工程师进来的主管，绝不是因为他喜欢在办公室里多养一个极客吉祥物，而是因为多招这名极客能帮他把某个（或某几个）能增收或降本的项目干完。

==写出优雅漂亮的代码不是目标，攻克高精尖的技术难题不是目标，写出零 Bug 的程序不是目标，用上最时髦性感的编程语言更不是目标。增加营收，削减成本，这才是你仅有的两个目标。==

现代管理学之父彼得·德鲁克（你以前可能没听过这号人，但在所有负责签支票的老板眼里，他就是先知级别的存在）提出过两个极其核心的概念：**利润中心（Profit Center）**与**成本中心（Cost Center）**。

- **利润中心**，是组织里负责往家里扛猪肉、直接赚钱的部门：比如律所里的合伙人、企业级软件公司里的销售铁军、华尔街上的金牌交易员等等。
- **成本中心**，则是除了利润中心之外的所有其他人。

**如果你希望拿到更高的薪水、赢得更多的尊重，并获得一切你所看重的职业发展机会，你就必须千方百计地把自己绑定在公司的“利润中心”上。** 要分清这两者一点也不难：随便找个脑子灵光的高中生，给他看一段百十来字的公司业务简介，他通常就能一眼指出哪块业务是这家公司的利润中心。如果你想去那家公司上班，就奔着它的利润中心去；如果一时半会儿进不去，那你要么换一家公司，要么在入职之后想方设法运作内部转岗，跳进利润中心去。

尤其值得注意的是，软件工程师通常属于**薪水高得离谱的“成本中心”**。这一特点会让所有读过 MBA 的高管头顶上的“成本优化雷达”疯狂作响。所谓“研发外包（Outsourcing）”这种绝妙主意就是这么来的，说白了就是：“既然这帮昂贵的成本中心每天都在搞一些我们虽然需要、但完全不关心的黑魔法，那干脆把他们全炒了，换成低工资国家里更便宜的成本中心吧。”（顺便提一句：只要你认真读完本文剩下的部分，你就完全不必把研发外包当成自己的职业威胁。）**从来没有任何一家公司会把自己的“利润中心”外包出去。** 谁要是敢在董事会上提议把利润中心外包，那简直是 MBA 圈子里的年度冷笑话，荒唐程度不亚于建议把公司的 Git 代码库删掉、改用一摞软盘来手工备份代码。

## 3. 别再自称“程序员（Programmer）”

在掌握预算的高管耳朵里，“程序员（Programmer）”这个词听起来就像是**“一个工资贵得反常的苦力，每天负责把一堆天书口诀敲进电脑，变成另一堆没人看得懂的天书”**。只要你管自己叫“程序员”，此时此刻就已经有人在琢磨怎么把你优化掉了。

你知道被工程师们奉为 SaaS（软件即服务）鼻祖的 Salesforce 吗？他们当年最核心的广告标语和销售卖点就叫**“不要软件（No Software）”**。这四个字翻译成说给企业老板听的大白话就是：“看到你们公司里养着维护内部系统的那帮程序员了吗？只要买了我们 Salesforce 的服务，你当场就能把他们裁掉一半，然后把省下来的人头费拿出一部分塞进你自己的年终奖口袋里。”（顺便说一句，Salesforce 这么干没有任何道德问题。我们软件工程这一行，本来干的就是用自动化淘汰低效人工的买卖。如果你觉得这不公平，那还是趁早回象牙塔去读个与现实世界无关的专业吧。）

那么，你应该怎么介绍自己？**请用你帮前东家在“增加营收”或“削减成本”上取得的具体战绩来定义自己。** 如果你是刚毕业的新人，还没有机会攒下这类实战战绩，那就展示那些能证明你具备“增收降本潜力”的事例，或者直接提出能帮对方增收降本的具体思路。

这世上有许多收入丰厚得惊人的专业人士，他们每天同样在写大量代码，但他们绝不会把自己描述成“靠写代码谋生的码农”：

- 最典型、最广为人知的例子就是**华尔街的量化宽客（Quants）**：他们把计算机代码和数学模型当作杠杆，比单靠人脑更快、更准地做出高风险高回报的交易决策；而这些决策的最终落脚点只有一句话：“我们帮公司赚了数十亿美元。”在行情好的年份里，一位成功的宽客光是一年的年终分红，就抵得上许多同等智商的普通工程师干上十年甚至一辈子的死工资。
- 同样地，哪怕是在 Google 这种被公认为“工程师天堂”的技术公司里，也存在着普通程序员与**“能让 AdWords 广告点击率提升 1% 的人”**之间的云泥之别（提示：那 1% 的点击率提升，在账面上可以确凿无疑地折算成数十亿美元的净收入）。前阵子我偶然逛到一个人的个人主页，他的职业履历简介只有短短一句话：**“我写了 Google 后端的计费结算核心代码，Google 97% 的营业收入都从这段代码里流过。”** 他现在的身份是一名天使投资人（也就是“财务自由的富豪”的礼貌同义词）。

## 4. 你绝不应该被自己选定的“技术栈”所定义

前几天我在 Twitter 上问年轻工程师们最关心哪些职场问题，结果一大群人跑来问我：“我到底该学哪门编程语言？该选哪套技术栈？”

我的回答只有四个字：**根本不重要。**

“Java 程序员是不是比 .NET 程序员挣得多？”**任何把自己定义为“Java 程序员”或者“.NET 程序员”的人，从起跑线上就已经输了**。原因有二：第一，他把自己降格成了一个“程序员”（记住前文说的，你不是）；第二，他亲手给自己贴上了狭隘的标签，把自己排除在了绝大多数好工作的大门之外。

在真实的商业世界里，上手一门全新的编程语言只需要花几个礼拜的时间；等你用它干上 6 到 12 个月之后，根本没人能看得出来你不是一辈子都在写这门语言。直到 2010 年 3 月，我还在帮客户开发庞大臃肿的企业级 Java Web 后端应用。相信我，根本没人在乎我以前写的是什么语言。如果今天有一家全栈使用 Python 的公司想找个懂技术的人帮他们大赚一笔，哪怕我这辈子一行 Python 代码都没写过，他们也绝不会因此把我就地淘汰。

真正优秀的工程师是极其稀缺的（比需要用到他们的商业机会还要稀缺得多），而且在软件行业的几乎每一个细分领域，目前都是典型的人才卖方市场。信息安全名企 Matasano 全员都在用 Ruby，但只要你是一名优秀的工程师，哪怕你完全不会 Ruby，他们照样会抢着招你。（来，跟我大声复述一遍：什么是优秀的工程师？**是有过帮公司增加营收或削减成本的实战记录的人。**）Fog Creek 软件公司大部分业务都跑在微软技术栈上，我甚至连 `ASP.NET` 怎么拼写都快忘了，但他们照样愿意给我发 Offer。

当然，市面上确实有很多人事制度僵化腐朽的公司，简历里只要少写了一个技术流行词（Buzzword），HR 就会直接把你筛掉。你本来就不该去这种蠢公司受罪；但如果你实在非去不可，你只需要花几个晚上和周末的时间，或者在当前的工作里顺手主导一次技术选型，就能光明正大地把那个关键词写进简历里。想在一家纯 .NET 公司里攒下 Ruby 实战经验？那就找个内部一次性小工具项目，直接用 Ruby 把它写出来。砰！从这一刻起，你就是一名名正言顺的“职业 Ruby 开发者”了，因为你写了 Ruby 代码，而且有人为此付了你薪水。（你觉得我在开玩笑？我当年在一家纯 Java 公司里就是这么干的。那个用 Ruby 写的一次性项目帮公司赚了 3 万美元，我老板自然乐得合不拢嘴，甚至**从头到尾都没问过这玩意儿到底是用什么语言写出来的**。）

## 5. 同事和老板通常不是你的朋友

你每天都会跟同事待在一起很长时间。日久天长，你也许最终会和其中一两个人成为莫逆之交；但在绝大多数情况下，三年之后你就会跳槽离开，除了在社交网络上保持礼貌的寒暄之外，**你根本不会特地邀请他们来家里吃晚饭**。而他们对你，也完全是一样的态度。你当然应该善待职场里遇到的每一个人（这既是做人的基本道德，顺带也能极大拓展你的人脉网络），但千万不要陷入“公司里人人都是我好哥们”的幼稚幻想。

举个最直观的例子：当你去参加求职面试时，哪怕坐在你对面的面试官是个满脸堆笑、和蔼可亲的 28 岁年轻人，看起来就像是年长几岁的你自己，请务必清醒地认识到：**他此刻正在与你进行一场商业交易。** 他不是你的朋友，你是一项工业生产流程里的原材料输入项，而他正试图以最低的采购价格把你买进公司。他跟你聊《魔兽世界》聊得热火朝天，那只是为了建立融洽的职业破冰氛围；一旦到了谈薪水和签合同的环节，他会（完全合乎职业道德地）干出你真正的朋友绝对不会对你干的事，比如想方设法把你的年薪往下砍掉几千美元，或者用道德绑架让你心怀愧疚地放弃陪伴真正朋友的周末时光、留在公司免费加班。

在日常工作中，你还会遇到其他同样和蔼可亲、同样不违背职场规则的同事，笑眯眯地向你提出完全违背你个人利益的建议：从“你刚干完的那个项目，汇报的时候应该算在我头上一份功劳”（当然话不会说得这么直白），到“咱们接下来应该采用这套方案，虽然它对你的履历没啥帮助，但它刚好能帮我刷满晋升所需的绩效指标”。当这种事情发生时，请千万不要大惊小怪。

## 6. 因为身处高手圈子，你严重高估了竞争对手的平均水平

这世上有数不清已经稳坐“高级软件工程师（Senior Engineer）”宝座、拿着高薪的职场老手，连最基础的 [FizzBuzz 编程测试](https://blog.codinghorror.com/why-cant-programmers-program/)都写不出来。去读读 Jeff Atwood 那篇著名的文章吧，读完你就知道现实有多让人哭笑不得了。

这件事给你的核心启示是：**那些你仰望已久、觉得自己“水平还不够格去应聘”的知名公司，你现在的真实水平大概率已经完全够格了。** 顶级公司招的确实是凡人里比较优秀的那拨人，但说到底，他们招的依然是凡人，不是神仙。

## 7. “看招聘广告 → 投简历 → 面试 → 拿 Offer”是求职的例外，而非主流

绝大多数好工作从来不会挂在公开招聘网站上，正如绝大多数真正抢手的优秀候选人也从来不会在公开求职市场上晃荡一样。

优质岗位的招聘信息，通常是以“喝啤酒聊天的速度”在私底下流传的，偶尔会有几封电子邮件充当润滑剂。流程往往是这样的：某家公司的拍板人意识到自己手头缺个人，于是跟身边的朋友和商业伙伴提了一嘴；其中某个人恰好认识一个合适的人选（可能是亲戚、大学室友、在某次行业大会上聊过天的同行，或者前同事）；接着中间人牵线搭桥，双方约出来喝杯咖啡聊了聊，当场就对录用条件达成了原则性一致。**直到这一步彻底敲定之后**，所谓的“补交一份简历 / 走一遍 HR 部门流程 / 发放正式 Offer”的过场戏才会正式上演。

对于那些你真正梦寐以求的好工作来说，这条规律更是准得惊人。比如很多极客都对“成为一家成功创业公司的第一号员工”充满向往，但历史上几乎没有任何一个“一号员工”是靠往 HR 邮箱投求职信进去的（部分原因在于，只有两个人的初创公司还没挨过足够的社会毒打，根本不可能设有 HR 部门。顺便忠告一句：你其实并不想当创业公司的“第一号员工”，要去就去当“最后一位联合创始人”）。想去 Google 上班？Google 有一套极其完善的正式内部推荐流程，只要有 Google 员工欣赏你，就能帮你一路开绿灯；如果某位 Google 大牛欣赏你到了骨子里，他们甚至还有好几种绕过常规流程的非正式招法（比如直接把你所在的公司收购掉。当一家公司账上趴着几百亿美元现金时，他们解决问题的方式总是充满了想象力）。

为什么绝大多数核心招聘都在私底下完成？原因有很多：一方面，只要把招聘启事公开发布出去，瞬间就会被成百上千份垃圾简历淹没（尤其在经济不景气的时候），投简历的人里 99% 都离谱到让人怀疑人生；另一方面，绝大多数公司自己的面试筛选能力又烂得惊人，如果不靠熟人知根知底的背书，单凭几轮八股文面试，很容易一不留神就把连 FizzBuzz 都写不出来的南郭先生招进门。

## 8. 网络连接（Networking）：不只是给 TCP 数据包用的

很多程序员一听“经营人脉（Networking）”就浑身起鸡皮疙瘩。其实所谓人脉网络，说穿了就两件事：**第一，结识那些在未来某个时刻能帮到你（或者你能帮到他们）的人；第二，给他们留下靠谱的好印象。**

结识同行的高质量场合有很多。行业技术大会、或者有工业界人士参加的学术研讨会是一类；本地的技术用户组（User groups）聚会是另一类。不过要记住，去参加本地语言用户组聚会的人，跟买门票参加行业商业峰会的人完全是两拨不同属性的人群，你要根据自己的目标去做针对性的投入。

**平时请尽己所能地去帮助别人。** 这不仅是做人的正道，而且人们心里都有一本账，谁在过去帮过自己或帮过自己身边的朋友，大家记得清清楚楚。如果有人向你求助，而你手头帮不上忙，但你恰好认识另一位能解决这个问题的行家，那就主动写封引荐信把他们撮合到一起。只要你把这事办得漂亮，这两边的人都会念你的好，将来遇到机会时自然也会乐意拉你一把。

你当然可以在互联网上结识天下英雄（老天爷，我太知道网上交友的威力了），但我们人类那颗从猴子进化来的大脑里，依然有一套古老的生物本能，使得**线下面对面的真人见面**具有无可替代的分量。我在网上认识过无数厉害的朋友，后来又在线下跟他们见了面；哪怕我们在网上神交时就已经做成了“靠一条好建议帮对方多赚了一大笔钱”这样的大事，线下见面的那一次真实握手，依然会让双方的信任关系迈上一个质的台阶。所以，平时一定要多写博客，多在 Hacker News 这类行业核心圈子里发声交流，但到了线下聚会和大会的时候，也请务必走出会场去跟大家握手见面。

## 9. 象牙塔里的学术界，与真实世界完全是两码事

**你的大学绩点（GPA）基本上没有任何用处**（除了极个别奇葩例外，比如某家著名的跨国广告巨头）。即便在某些公司里 GPA 有一丁点作用，它也仅仅决定了你的简历能不能通过海选初筛、拿到第一轮面试机会。但只要你读懂了前文的内容，你就明白海投简历根本不是获取面试的主渠道。因此，千万不要花巨大的精力去死磕那点边际收益为零的数字：把 GPA 从 3.8 刷到 3.96 不会帮你多换来哪怕一场面试；你有刷高分那工夫，还不如去练练怎么得体地约业内前辈出来喝杯咖啡。

**你的主修专业和辅修专业名称同样无关紧要。** 工业界里绝大多数拍板招人的决策者，哪怕拿枪指着他们，他们也分不清“计算机科学学士”和“数学学士”到底有啥区别。我读大学的时候曾因为选课学分上的一点小差池，差点拿不到“主修计算机科学的理学学士（Bachelor of Science with a major in Computer Science）”，只能拿“计算机科学理学学士（Bachelor of Science in Computer Science）”，当时我的学业导师神色凝重地告诉我前者比后者尊贵得多，害得我当场急哭了。只有象牙塔里的官僚才在乎这种文字游戏，真实世界连眼皮都不会抬一下。

你的大学教授或许很懂学术界的求职市场是怎么运转的（长话短说：工科教职市场低效得令人发指，而文科教职市场更是崩坏到了常人无法理解的地步），但他们对校外真实商业世界的理解，往往天真得像堂吉诃德一样。比如，教授们总是热衷于劝你留校继续读研、读博，原因很简单：第一，在他们自己的认知里，多读个学位听起来总归是个好主意；第二，他们太喜欢手底下有一群每个月只领着泡面钱、却能没日没夜帮他们干活发论文的廉价学术苦力了。请记住，一个具备独立科研能力的聪明人，如果直接去工业界上班，市场起薪轻轻松松就是每年 8 万到 10 万美元以上。**那笔钱能买下的方便面，足够把整个实验室淹没。**

当年带我做本科科研项目的教授曾满怀慈爱地向我抛来橄榄枝：只要我愿意签字卖身给他干上 4 到 6 年，他就给我留一个实验室名额、免除学费，外加每年整整 **12,000 美元**的生活津贴！这笔买卖在且仅在一种情况下是划算的：你刚从一个低收入国家移民过来，急需一位大学教授出面替你跟移民局打交道办合法签证。

如果你真的很迷恋大学校园里的学术氛围，那完全没问题。去买个双肩书包背在背上，你随时可以大摇大摆地走进全美国任何一所大学的任何一栋教学楼里旁听。**买个双肩包，可比留在学术界打黑工便宜太多了。** 在工业界，你同样可以过上充满智识乐趣的思考者生活，而且办公室政治少得多，收入更是高出天际。如果你实在对发表学术论文有执念，在企业里工作也照样可以往期刊投论文（虽说等你彻底逃离了学术界那团扭曲心智的瘴气之后，你大概率会清醒地反问自己：把文章发在没人看的学术期刊上，跟写一篇高质量技术博客发给全网最聪明的一群同行阅读相比，到底哪一个对个人和社会更有价值？）。

## 10. 工程师到底能挣多少钱？

这个问题本身就问错了。正确的问题应该是：**“工程师通常会为了什么样的综合薪酬包（Offer）而工作？”** 因为基本工资只是用来激励你的众多杠杆之一。而这个问题的答案，说出来可能不太解渴：**“天差地别，什么价码都有。”**

大体而言，有几条普遍规律：
- 大公司给的综合待遇（现金、福利、补贴等）通常比创业公司高；
- **“感知价值”高**的工程师，赚得比“感知价值”低的工程师多；
- 资深工程师赚得比初级工程师多；
- 高生活成本地区（如硅谷、纽约）的薪水比低生活成本地区高；
- ==擅长薪资谈判的人，赚得比不会谈判的人多得多。==

我们从小到大接受的社会文化规训，都在反复告诫我们“绝对不要在公开场合谈论薪水”。但这种禁忌绝非放之四海而皆准的自然法则。在许多文化里，职场社交场合聊薪水是再正常不过的事。（比如在日本，如果你是一名中产阶级男性，你在第二次相亲约会时、在业余足球俱乐部里、或者跟常去的寿司店老板聊天时，大家完全会自然而然地问起你的准确年薪；如果你自己开公司，你可能会对个人净资产守口如瓶，但你跟同行讨论员工薪水标准时的自然程度，就像程序员讨论编译器优化一样家常便饭，毫无尴尬可言。）如果我是一名马克思主义学者或者阴谋论者，我一定会怀疑美国中产阶级这种“羞于谈钱”的文化禁忌，完全是资本家为了维护雇主利益、打压雇员议价权而蓄意设计出来的思想钢印。

因此，在你跟任何一家目标雇主正式谈薪水之前，一定要先找一位目前就在那家公司（或同级别公司）干着类似岗位的同行聊一聊，摸清这个岗位的真实薪资带宽。现在都什么年代了，你完全可以在网上轻松找到这些人（LinkedIn、Facebook、Twitter 以及你现实中的朋友圈，都是极好的打听渠道）。

除了基本工资之外，工程师通常还会拿到一整套福利包。以美国为例，真正值得你花心思算清楚的大头有两项：一是医疗保险（传统上由雇主承担绝大部分甚至全部保费），二是退休金匹配计划（比如公司承诺按你薪水的 X% 等额匹配往你的 401k 养老账户里存钱）。这笔福利的价值算起来再简单不过：它就等于直接给你加薪 X%。（这是白捡的钱，所以无论如何一定要把个人缴纳额度拉满到雇主匹配的上限，然后全部买成低成本指数基金，扔在那里 40 年不用管。）

至于招聘启事里吹得天花乱坠的其他小恩小惠，比如“免费畅饮气泡水”、“免费午餐”、“免费报销技术买书钱”等等，**它们本质上都只是社交信号（Social signals），而非实质薪酬**。当一位老板拍着胸脯对你说“来我这儿上班，汽水随便喝”时，这句话其实透露了他是如何管理公司的、他想招什么样的人，以及他打算怎么对待员工。（这句话潜台词往往是：“我喜欢用 2 毛钱一罐的廉价糖水，把这份苦差事包装得像大学社团一样酷，用来忽悠没见过世面的年轻工程师；这样我既能每年省下好几万美元的真金白银薪水，又能顺便鼓励他们喝垮自己的身体。”顺便说一句，我自己其实挺爱喝汽水的。）

你要学会冷静地解读这些社交信号：如果一家公司释放出的信号是“我们非常舍得花真金白银送员工去进修学习”，那它大概率是一家值得效力的好公司；但**千万不要为了贪图那点你自己花几十块钱就能买到的零碎福利，而放弃数以万计的现金薪酬。**

## 11. 我该如何提高薪资谈判能力？

这个话题展开写足可以单独成书。这里给你浓缩成最核心的六条军规：

1. **a) 牢记你兜售的到底是什么**：你卖给公司的是**解决商业痛点的方案（增加营收或削减成本）**，而不是你的编程语法熟练度，更不是你那张英俊的脸庞。
2. **b) 带着恰当的自信积极争取**：像一名有职业操守的专业人士那样去据理力争，因为坐在谈判桌对面的雇主此时此刻也正在这么干。谈判的目标是达成一份双方共赢的协议，而不是对方说啥你都唯唯诺诺地点头说“好”。
3. **c) 警惕询问前司薪水的陷阱**：当 HR 笑眯眯地问你“你上一份工作的薪水是多少？”时，翻译成雇主黑话就是：**“请给我找几个可以合法压低你工资的理由吧。”** 请务必聪明地应对这个问题。
4. **d) 永远准备好你的还价方案（Counteroffer）**：而且要学会在现金之外你所看重的其他维度上灵活还价。如果对方受限于职级红线实在没办法再提高基本月薪，那就顺势要求增加带薪年假天数、签字费或居家办公天数。
5. **e) 严守谈钱的最佳时机**：谈薪水唯一正确的时机，是在**双方已经达成原则性共识（即只要价格谈拢，他们就非招你不可）之后**。这通常发生在整个招聘流程的最末端，此时公司已经在你身上投入了大量的时间、精力与沉没成本；具体来说，**绝对不要在刚面试的时候就亮出底牌谈钱**。请记住，到了流程最后一步，如果因为谈崩而对你说“算了，那我们不招你了”，公司自己也要承担极其高昂的重新招聘成本；因此，只要你在他们给出的初始报价基础上，有理有据地要求再往上加几千美元并温和而坚定地咬住不放，绝大多数公司根本不会为了这点小钱而掀翻整张谈判桌。
6. **f) 去读一本谈判断的经典好书**：市面上关于谈判学的优秀著作汗牛充栋，我个人非常推荐《谈判力》（*Getting To Yes*）。有一件事常让我感到匪夷所思：**谈判技巧是一项能在你整个职业生涯里每年为你多赚几千甚至几万美元的核心技能**，可无数聪明的工程师宁可花几百个小时去钻研某个火了三个月就过时的前端框架细节，却觉得花一个周末专门学习谈判学是一件不可理喻的事。

## 12. 如何评估创业公司给你的期权（Equity Grant）？

请掏出一颗百面骰子（d100）扔一下。（什么？你不是跑团极客？好吧，那就在脑子里跑一下 `rand(100)` 随机数函数吧）：

- **掷出 `0 ~ 70`**：你手里的期权是一文不值的废纸。
- **掷出 `71 ~ 94`**：你手里的期权最终能变现出一笔还算不错的辛苦费，加起来刚好差不多等于你这几年为了在创业公司拿低薪苦熬、而放弃去大厂拿高薪厚禄所损失掉的差价总和。
- **掷出 `95 ~ 99`**：你手里的期权变成了一笔足以改变人生命运的巨款。虽然你依然不会觉得自己是顶级富豪（因为在你的熟人圈子里你肯定不是最有钱的那个，毕竟过去这几年跟你一起并肩作战的老板和高管们，按持股比例算肯定比你还要富得多），但你们家七大姑八大姨这辈子再也不会数落你当年为什么没去考公务员、当医生或者进某行某业了。
- **掷出 `100`**：你押中了下一个 Google，获得了连贪婪之神做梦都想不到的泼天富贵。恭喜你！

眼尖的读者应该已经注意到了：无论是标准的百面骰子（`00~99`）还是编程语言里的 `rand(100)`（生成 `0` 到 `99` 的整数），**其实根本就不可能掷出 `100` 这个数字。**

## 13. 你为什么对创业公司期权这么悲观？

因为绝大多数年轻工程师都**严重高估了自家创业公司存活并成功的概率**，同时又**严重高估了即便公司成功上市或被收购后，最终能分到自己碗里的那块蛋糕比例**。

有空去 Hacker News 或者 Venture Hacks 上搜搜什么叫**“股权稀释（Dilution）”**，什么叫**“优先清算权（Liquidation preferences）”**。读完之后请记住一个冷酷的事实：投资人和创始人在商业条款博弈上的段位，比你在写代码这件事上的段位还要高得多；不妨设想一下，如果在一套软件系统面前摆上几个亿美元的真金白银，你能用代码玩出多少花样来？那帮金融老手在股权分配协议里就能玩出同样多的花样。

## 14. 对于刚毕业的应届生来说，去创业公司是好的职业起点吗？

大概率的结局是：你在接下来的两年里没日没夜地拼命苦干，然后公司无声无息地倒闭了，你丢了工作，只能灰头土脸地再去下一家创业公司找活干。

如果你真的那么向往在毕业两年后投身创业浪潮，其实有一条稳健得多的路线：**毕业后先去一家顶级大厂干上两年，攒下一笔丰厚的启动资金（Warchest），摸清一个行业的真实商业运作逻辑，顺便结识一帮靠谱的业内精英，然后带着钱、认知和人脉，自己出来创办一家公司。**

更何况，你在初创小公司里上班，平时接触到的往往也都是其他初创小公司的人，两年之后他们大概率也没钱雇你；而你在行业大厂里上班，平时结识的都是各大企业的同行骨干，两年之后，他们当中很多人要么自己手里就有招人名额，要么能直接在招人拍板者耳边说上话。

## 15. 那么，你到底推不推荐去创业公司上班？

去创业公司上班不仅是一条职业路径，**它本质上更是一种生活方式的选择（Lifestyle choice）**。这跟去华尔街投行上班、或者留在大学学术界搞科研是一模一样的：它们代表了三种截然不同的人生过法。

这世上有很多人出于他们自己的利益考量，会拼命向你推销某种生活方式，把它包装成“最符合你个人利益的唯一解”。如果你发自内心地享受创业公司那种肾上腺素飙升的折腾生活，那就放手去干吧！但如果你其实只喜欢其中的某几个局部特征，请记住，职场上的很多体验其实是可以“单点（A la carte）”的，完全不必为了喝口醋而买下整家醋厂。

举个例子：如果你既想捣鼓最前沿的尖端技术，又想每天下午 5 点半准时下班回家陪孩子吃晚饭，你完全可以在许许多多大型科技企业里找到同时满足这两个条件的工作。

（没错，我是认真的。只要某项前沿技术能帮大公司创造商业价值，大公司绝对舍得砸重金去研发。当然，大公司里确实也有写不完的 CRUD 增删改查应用；可话说回来，创业公司里写的不也全都是 CRUD 应用吗？无非是创业公司比大厂更擅长把“写个增删改查网页”这件事包装得热血沸腾罢了。不信你看电影《社交网络》，前一个小时演的就是怎么把一个 CRUD 校园交友网站吹成改变世界的性感神话，后一个小时演的则是一出极其狗血的、发生在两个直男之间的离婚争产肥皂剧。）

## 16. 你最重要的职业技能，其实是“沟通能力”

还记得前文说的“公司雇工程师不是为了写代码，而是为了创造商业价值”吗？在求职和职场上，决定你能否拿到好机会的最核心特质，其实是**“让别人相信你能创造价值的能力”**。请注意，这种能力与你“实际创造价值的能力”并不总是完全重合的。

我认识一些水平顶尖的编程天才，在现实中却患有近乎病态的沟通障碍，根本无法与人正常交谈。结果就是：第一，大家普遍不愿意跟他们共事；第二，大家会严重低估他们创造价值的能力，因为人类天性就是通过语言交流来评估一个人的能力的，而这些天才根本就没有实现这套“人类沟通通信协议”。

反过来，许多跟我打过交道的人都会习惯性地以为我是他们认识的水平最高的程序员之一，原因其实只有两条：第一，网上确实有一些公开可见的证据，证明我会写代码；第二，**我的书面写作能力与口头表达能力真的非常、非常出色。**

（曾几何时，我一度带着技术人的自卑，把自己定义为“编程水平略低于平均线的人”。后来我才慢慢顿悟：一来我当年对同行平均水平的估计严重失真；二来商业世界真正筛选和奖赏的根本就不是纯编码技巧；三来过分谦虚只会严重损害我自己的利益。如今，如果有人问我“你写代码水平到底怎么样？”，我绝不会去扯什么算法复杂度，而是会直接给他讲故事：讲我写的软件系统如何帮助全美数百万儿童学会了阅读，或者我写的系统如何确凿无疑地帮客户公司多赚了数百万美元。至于我的纯编码技术到底排在正态分布钟形曲线的哪个百分位上，全世界根本没有一个人关心，我又何必自己跟自己过不去呢？）

==沟通是一门纯粹的技能。只要刻意练习，你就一定能越练越强。== 其中最关键的一项子技能是：**面对一个不懂技术的非本专业人士（而且他没有任何先验理由非得喜欢你不可），你能不能用最简短、最清晰、最自信的语言，在三句话之内让他听懂你是如何创造商业价值的？**

如果你在尝试解释自己的工作时，嘴里老是忍不住蹦出各种技术黑话（比如“我通过优化复合索引，把 99 分位的长尾查询响应时间缩短了 200 毫秒……”），请立刻把这些词全删掉，重新组织语言再试一次。无论面对的是一个聪明伶俐的 8 岁小孩、你们公司的首席财务官（CFO），还是另一个技术方向的程序员，你都应该能够迅速切换到最恰当的抽象层级，用对方听得懂的语言把你做的事讲得明明白白。

## 17. 你经常需要干“企业级销售（Enterprise Sales）”的活，哪怕你当年学计算机就是为了躲开它

什么是企业级销售？就是走进一家大公司，说服那里的决策者掏出六位数甚至七位数的真金白银，买下一套能帮他们增加营收或削减成本的系统。

==你人生中参加的每一场求职面试，本质上都是一场企业级销售。== 在这场销售里，组织政治、人际信任与沟通技巧占了千钧之重，而纯粹的技术细节真相反而没那么重要。

甚至当你坐在会议室里跟同事开会，试图说服大家采纳你的技术重构方案时，你干的依然是企业级销售的活。如果你的工作职责是“把事情做成（Getting stuff done）”，那么**“说服别人配合你把事情做成”**就是你最核心的岗位技能。请花点真功夫把这项技能练好：这意味着你要学会写出条理清晰的备忘录和邮件，学会在私下交谈、团队会议乃至 PPT 演示中高效地说服他人；意味着你要懂得如何为一项技术提案算清楚商业投入产出账（Business case）；也意味着你要有成熟的工程判断力，明白在某些时候为了达成商业目标而主动在技术完美主义上做出妥协，恰恰是最正确的职业决定。

## 18. “过分谦逊”绝不是一项有助于职业发展的美德

许多工程师都有点自信心不足的毛病（嗨，说的就是当年的我自己）。还有很多人从小接受的家庭与文化教育，都在推崇“做人要低调谦虚，千万不要居功自傲”。

但现实是：**现代商业世界在评估一个人的能力与贡献时，根本不会奖赏你的谦逊。** 无论是在求职面试、职场协作还是日常交往中，你最应该追求的黄金语调都应该是：**“克制、自信的专业主义（Restrained, confident professionalism）。”**

如果你参与了一个团队项目并取得了圆满成功，除非你现在的江湖地位已经高到了“所有人一听就知道你是在客套自谦”的程度，否则千万不要一上来就说“这全都是团队的功劳，我没做什么”。试着把话术换成：**“我非常荣幸能协助团队推进这个项目，并主导了其中关于 `[你的专业领域]` 部分的核心攻坚。”**

对着镜子把这句话练习一千遍，直到你能面不改色、自然坦荡地脱口而出为止。你心里可能会犯嘀咕，觉得这么说是不是有点夸大自己的功劳了？去他的吧！一个在快餐店里夹火腿片的店员，如果在简历上声称自己“主导了食品生产线全流程优化工程”，那才叫夸大其词；而你是一名实打实的软件工程师，你手里的代码像魔法一样实实在在地改善了成千上万人的生活与工作。如果在一个至关重要的项目里，数据库架构那摊事确实是由你全权负责盯下来的，那么**毫无疑问，你就是主导了决定该项目成败的数据库核心工程**。

这就是职场这场游戏的真实规则。如果你因为不好意思认领功劳而吃亏，那就好比一个棒球击球员因为觉得“盗垒不够君子”而拒绝盗垒一样：你既没有因此占据任何道德制高点，你只是单纯把球打得很烂而已。

## 19. 所有的商业决策，最终都是由一两个跟黑猩猩基因高度相近的多细胞生物拍板的，而不是由规则或算法决定的

人终究是人，不是精密运行的计算机。在人类社会里，“社交梳理（Social grooming）”是一项重要得惊人的生存技能。

人们在会议上支持某个方案，往往仅仅因为提方案的人是自己的朋友，哪怕旁边明明有另一个更优的客观方案；人们天然会对跟自己一起吃过饭、喝过酒的人抱有好感（市面上有一本畅销商业书就叫《别独自用餐》，非常值得一读，光是这个书名就已经把人类社交的真相扒得底裤都不剩了）；人们也总是本能地偏爱那些“看起来跟自己是一类人”的同类，而疏远那些看起来格格不入的异类。（这种人性本能既可能带来好事，也可能带来偏见；但唯有先坦然承认它的客观存在，你才能迈出利用规则保护自己、成就自己的第一步。）

与此同时，字面意义上的**个人仪表打理（Actual grooming）**也至少有着中等以上的重要性，因为人类大脑有着一套极其容易被“外貌与气场”黑进去的浅层视觉漏洞：只要你在特定场合穿上得体的衣服、保持清爽专业的仪表、用自信沉稳的语调说话，别人对你的态度就会发生立竿见影的偏转。

一套合身的体面西装，价格大概也就跟一台普通电脑显示器差不多。你一年到头可能也穿不上两回，但到了真正需要穿它的关键时刻，你会无比庆幸自己衣柜里挂着这么一套战袍。听我一句劝：平时我去市政厅或政府机构办事时，如果穿着日常的帽衫牛仔裤，办事员看我的眼神就像在看一个笨拙倒霉的二十多岁穷小子；可只要我换上那身剪裁合体的西装走进去，他们立刻就会像接待跨国公司 CEO 一样对我毕恭毕敬。事实上，我本来就是个笨拙的二十多岁跨国公司 CEO；但当我需要从官僚机构手里拿到优待时，我有权决定把哪一面展示给他们看。

（熟悉我生意的朋友可能会吐槽我居然管自己的小公司叫“跨国公司”，因为这跟大众脑海里浮现的跨国巨头根本不是一回事。抱歉，这只是一个简单的社交话术技巧。如果你觉得别人发现真相后会因为感觉被操纵而恼火，那我也只能说，这世上同样有很多人痛恨西装革履，但这并不妨碍西装在关键场合发挥巨大的价值。在什么山头唱什么歌；顺便提一句，当你面对的是随时有权把你驱逐出境的外国移民局官员时，“在技术定义上严格属实的回答”永远是世界上最棒的回答。）

## 20. 归根结底，你这一生的幸福感，绝不会由你的职业成就来主宰

去跟上了年纪的长辈聊聊，或者去看看社会学家们追踪了几十年的实证研究吧：到了人生终点回望时，**家庭、信仰、热爱与亲密关系所带来的真实幸福感，完全碾压了所谓的职场头衔与银行卡余额**（另见《[人生的尾声](/translations/the-tail-end/)》与《[如何做出卓越的工作](/translations/greatwork/)》）。

所以，请用全局的眼光去优化你的人生函数。你的事业当然很重要，尤其在二十多岁刚起步的年纪，它看起来几乎像是生命里唯一重要的全部；但随着岁月流逝，你极大概率不会永远这么认为。

==请为了生活而工作，永远不要为了工作而活着。==
