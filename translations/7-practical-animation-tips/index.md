# 7 个实用的 UI 动效技巧（7 Practical Animation Tips）

> 原文：[7 Practical Animation Tips](https://emilkowal.ski/ui/7-practical-animation-tips) · 作者：Emil Kowalski · [阅读英文原版](./en.md)

![7 个实用的 UI 动效技巧](/images/7-practical-animation-tips/7-practical-animation-tips.webp)

职业生涯早期，我犯过一个错：总觉得设计，尤其是动效，是一门全凭天赋的艺术，要么开窍，要么一辈子摸不着门道。

那些好看的界面动效看起来都像魔法，而且离自己很遥远。

诚然，做好动效需要慢慢培养直觉，但在练出那种“魔法”之前，其实有很多现成的小技巧，直接用上就能让动效质感明显提升。

下面这 7 个简单实用的思路，你今天就可以用到项目里。

## 1. 给按钮加上按压缩放

好的界面应该让用户觉得它随时在回应自己。用户每做一个操作，都应尽量第一时间给出反馈：提交表单时展示加载态，复制到剪贴板后展示成功提示。

想让界面立刻显得更跟手，一个很简单的办法，就是在按钮被按下时加上轻微的缩小效果。给 `:active` 伪类设置 `0.97` 的缩放比例就够用了。

> **[译者注：按钮按压 CSS 示例]**
>
> 原文页面在此处附有可直接点击对比的交互演示（左侧无缩放，右侧按下时缩放至 `0.97`）。在项目中用纯 CSS 写出来只需几行：
>
> ```css
> .button {
>   transition: transform 160ms ease-out;
> }
> .button:active {
>   transform: scale(0.97);
> }
> ```

## 2. 不要从 `scale(0)` 开始做缩放

如果元素从 `scale(0)` 开始放大，动效往往会显得有点别扭。试试把初始缩放值调高一些（`0.9` 以上），整个变化过程会柔和、自然、克制得多。

在原文的对比演示里，作者用的是 `0.93` 作为初始缩放值。

`scale(0)` 之所以看着不对劲，是因为元素像是凭空冒出来的。较高的初始值更贴近现实世界的物理观感：就像一只气球，哪怕放光了气，也依然有可见的轮廓，不会彻底消失成一个点。

## 3. 连续切换 Tooltip 时不要再加延迟

文字提示（Tooltip）首次出现前应该有一小段延迟，防止鼠标无意扫过时频繁误触。但一旦某个 Tooltip 已经展开，鼠标再移到同组的其他图标上时，新的 Tooltip 就应该零延迟、无过渡动画地立刻切换。这样既保留了首次防误触的作用，又让连续浏览显得顺畅。

Radix 和 Base UI 这两个无样式组件库，在已有 Tooltip 打开时都会自动跳过后续延迟。Base UI 还进一步支持跳过过渡动画：只要选中 `data-instant` 属性，把 `transition-duration` 设为 `0ms` 即可。

实现样式大致如下：

```css
.tooltip {
  transition:
    transform 0.125s ease-out,
    opacity 0.125s ease-out;
  transform-origin: var(--transform-origin);

  &[data-starting-style],
  &[data-ending-style] {
    opacity: 0;
    transform: scale(0.97);
  }

  /** 禁用连续切换时的过渡动画 */
  &[data-instant] {
    transition-duration: 0ms;
  }
}
```

## 4. 选对缓动曲线

缓动曲线（Easing）描述的是属性在一段时间内变化的快慢节奏，它是所有动效里最核心的部分。

==缓动选对了，普通的动效也能显得很高级；缓动选错了，再好的动效也会显得别扭==。

如果元素正在进入或离开屏幕，优先用 `ease-out`。它一开始速度很快，能立刻给用户一种“界面有反应”的跟手感。

原文中对比了两个下拉菜单：左边用 `ease-in`，起步慢；右边用 `ease-out`，起步快，整体体感也就显得更快。两个下拉菜单的时长完全相同，都是 `300ms`，但用 `ease-in` 的那个摸起来就是显得迟钝。这就是缓动曲线带来的差别。

你当然可以把时长缩短来勉强迁就 `ease-in`，但这种曲线本来就不是为 UI 动效设计的：它把加速留在了*末尾*，和界面交互想要的效果正好相反。

除了方向，文章里的大多数示例还用了自定义缓动曲线。CSS 内置的缓动曲线力度通常偏弱，所以我自己几乎不用它们。相比之下，自定义曲线显得更有张力。

你依然遵循同样的缓动原则，只是把内置的 `ease-out` 换成自定义版本，表现力会强不少。网上有很多现成的缓动曲线参考站，我推荐 [easings.co](https://easings.co/)。

> **[译者注：关于自定义缓动曲线的延伸阅读]**
>
> 如果想系统了解 `cubic-bezier` 参数、各类内置曲线与自定义 `ease-out` 的具体写法，可以对照阅读本站的[《CSS 动画缓动曲线指南》](/posts/css-easing/)。

## 5. 让动效感知变换原点

想让气泡卡片（Popover）或下拉菜单显得更顺眼，一个有效做法是让它“感知原点”：元素应该从触发按钮所在的位置展开缩放。这需要用到 CSS 的 `transform-origin`，但它的默认值是 `center`，在绝大多数弹出层场景下都是错的。

当弹出层在水平和垂直方向上的原点都与触发器错位时（比如位于触发器右上角），有没有校准原点的差异会非常明显。

Base UI 和 Radix UI 都通过 CSS 变量内置了原点感知支持，直接把对应变量赋给 `transform-origin`，组件就会自动算出正确的展开起点：

```css
.radix {
  transform-origin: var(--radix-dropdown-menu-content-transform-origin);
}

.baseui {
  transform-origin: var(--transform-origin);
}
```

你可能会觉得这种差别太细微了，甚至压根看不出来。其实，你或者用户有没有刻意注意到，并没有那么重要。==单个不易察觉的细节叠加到一起，就会产生复利，变成肉眼可见的质感==。

无数这类微小的细节汇集起来，最终会撑起一种令人惊艳的整体体验，就像一千个轻柔却音准一致的声音合在一起合唱。

## 6. 保持动效迅捷

哪怕实际加载耗时一模一样，转得更快的加载指示器（Spinner）也会让人觉得应用加载得更快。这提升的是用户的“感知性能”。

同样地，`180ms` 的下拉选择动效，用起来明显比 `400ms` 的更跟手。

作为一条经验法则，==UI 动效的时长通常应该控制在 `300ms` 以内==。

而对于那些用户每天会看到几十次甚至上百次的高频操作，干脆把动效或悬停过渡彻底去掉。它们不会给用户带来惊喜，只会很快变成干扰，让整个界面显得拖沓。

关于这一点，我在[《你不需要动效（You Don’t Need Animations）》](https://emilkowal.ski/ui/you-dont-need-animations)一文中有更详细的讨论。

## 7. 实在调不顺时，加一点模糊

如果你已经换了好几种缓动曲线和时长，动效看起来还是哪里不太对劲，可以试着加一点点 `filter: blur()`，用来遮盖过渡里的瑕疵。

在原文的按钮状态切换示例里，左边是纯粹的淡入淡出交叉过渡，右边在切换瞬间加了 `2px` 的高斯模糊，同时配合了第 1 条的 `0.97` 按压缩放。第二个按钮的切换观感明显顺滑得多。

模糊在这里起作用的原因，是它弥合了新旧两个状态之间的视觉断层。不加模糊时，眼睛会清晰看到两个分离的对象在硬切，显得生硬；加上轻微模糊，就能把两个状态柔和地揉在一起，让眼睛自然脑补出一段顺滑的过渡。
