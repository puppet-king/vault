# 用间隔重复软件（SRS）彻底记住一门编程语言

> 原文：[Memorizing a programming language using spaced repetition software](https://sive.rs/srs) · 作者：Derek Sivers（2013 年 1 月） · [查看英文原版](./en.md)

这套方法我已经坚持用了一年，==这是我写代码 14 年来发现的最管用的学习技巧==。

## 起因

我算是个半路出家的中级程序员，没读过科班。当年完全是被逼上梁山：我做的网站越长越大，又雇不起程序员，只好自己抱来几本讲 PHP、SQL、Linux 和 Apache 的书，现学现卖，学到刚好能把网站跑起来的程度，然后靠着这点够用的底子硬撑了好些年。

直到后来，我有机会和一位真正的高手并肩写代码，他掌握的“编程词汇量”彻底震撼了我。各种命令和函数就像长在他手指上一样，行云流水般地敲出来。明明用的是同一门语言，可==因为他把大量的语法和库函数都烂熟于心==，站在他旁边，我简直像个站在大学教授面前的小学生。我也非常想拥有那种信手拈来的流畅感。

这件事让我开始反思：这么多年来，我到底有多少东西是**刚学会转头就忘光了**的？平时看书或读技术文章，看到某个很实用的新特性，动手试了一次觉得不错；可只要一忙别的事，很快就会把它抛在脑后，下次写代码时又退回了自己最习惯的老路子。

我想把一门语言里的命令、函数和技巧真正刻进脑子里，不再边学边漏，让它们随时待命，用的时候能够脱口而出。

## 间隔重复（Spaced Repetition）

当你接触到一个新知识点时，如果不把它反复拉回脑海的最前端，很快就会彻底遗忘。

当然，你也可以靠“泡在某门语言里”来被动复习，比如强行多写多看，碰巧遇到刚学过的词或语法，就能顺带加深一次印象。但这种靠运气的复习效率太低了。

记忆心理学的研究早就证实：==巩固一个新知识点最有效、最省力的时机，恰恰是在你快要忘记它的前一刻==。

[![遗忘曲线](https://m.sive.rs/images/forgetting-curve-srs.jpg)](http://quantifiedself.com/2026/06/spaced-repetition-and-learning/)

比方说，你刚学了一个外语新单词，最理想的复习节奏是：刚听完过几分钟考自己一次，隔几个小时再考一次，接着是第二天、2 天后、5 天后、10 天后、3 周后、6 周后、3 个月后、8 个月后……如此循环几次之后，这个词基本就永久刻进你的长期记忆里了，往后只需要极偶尔地唤醒一下即可。

**间隔重复软件（Spaced Repetition Software，简称 SRS）干的就是这件事。** ==你只需要把想记住的知识点喂给它，每天让它抽考你一次，它就会根据你的答题反馈自动安排下一次复习的间隔。== 每次抽考完一道题，如果你觉得轻而易举，它就会隔很久才再拿出来问你；要是你卡壳没答上来，它几分钟后就会再问你一遍，直到你彻底答对为止。

去 [apps.ankiweb.net](https://apps.ankiweb.net/) 下载 **Anki** 吧。这是一款免费、开源且口碑极佳的间隔重复软件。

说到这儿，你大概已经明白我打算怎么把它用在编程上了。

试想一下：如果你能==把自己主攻的编程语言彻彻底底记在脑子里==，会是什么体验？每一个命令、每一个参数、每一个内置函数，甚至成百上千个常见问题的最优写法，全都随时在指尖待命。想象一下，当你读完一份官方文档或一本技术专著后，**能把里面的每一个细节永久记住**，那该有多痛快？

铺垫就到这里，下面直接讲具体怎么做。

## 第一步：先真正搞懂，再做卡片

**闪卡（Flashcards）的作用是帮你*记住*已经学会的东西，而不是代替学习。**

在把某个知识点做成卡片之前，==你必须先亲手试过、真正理解了它的来龙去脉==。只有彻底搞懂之后，才去建卡。

（这也是为什么直接下载别人现成的牌组通常没什么用。因为对制作者来说，卡片只是唤醒记忆的锚点；没经历过理解的过程，看别人的卡片只是死记硬背。）

## 第二步：把知识拆解成极小的原子事实

接下来你要制作大量的抽认卡：正面写问题，背面写答案。

如果只是拿它来背外语单词，卡片格式再简单不过了：正面写外语单词或短语，背面写母语释义（反过来再做一张）。

但如果你用它来学编程或其他专业技能，做卡片就需要花点心思和巧劲了。

你需要读完一整段技术说明，从中挑出核心知识点，把它们拆解成最小颗粒度的事实，再改写成一道道用来考“未来的自己”的小问题。这件事一开始需要练一练，以下是我在一年实践中总结出的几个最省时间的制卡窍门：

### 1. 把文字描述转成代码题

假设你在读编程教程时，看到一段讲解某个特性的文字：

> “加法运算符（`+`）……如果两个操作数中只有一个是字符串，另一个操作数也会被转换为字符串，最终结果是两个字符串拼接后的结果。”

你先打开终端自己敲一遍、改几个值试一试，搞明白之后，就可以做一张这样的卡片来记住它。

**卡片正面（问题）：**

```js
var a = 5 + '5';
// a 的值是什么？
```

**卡片背面（答案）：**

```text
'55'
只要 + 号任意一侧是字符串，另一侧就会先被转换成字符串，再按字符串拼接。
```

### 2. 故意给未来的自己“挖坑”

写代码时经常会遇到一些反直觉的“坑（gotcha）”，也就是常见的易错点或奇怪的语法特性。比如文档里写着：

> “如果向 `new Array` 构造函数只传入一个数字参数，它会创建一个长度为该数字的空数组；传入其他任何参数组合，则会创建包含这些参数的数组。”

你亲手试过、弄懂之后，不妨故意做两张长得很像的卡片，专门用来给未来的自己下套：

**卡片 1 正面：**

```js
var a = new Array('5');
// a 是什么？
```

**卡片 1 背面：**

```text
包含一个元素的数组，元素为字符串 '5'：['5']
```

紧接着，再做一张几乎一模一样的双胞胎卡片：

**卡片 2 正面：**

```js
var a = new Array(5);
// a 是什么？
```

**卡片 2 背面：**

```text
长度为 5 的空数组。
```

软件每天抽考时会打乱卡片顺序，这种刻意设计的对比题很容易让你冷不防掉进坑里，从而对这个边界情况印象深刻。

你还可以设计更隐蔽一点的陷阱题，让这些易错点始终保持鲜活：

**卡片正面：**

```js
var a = [20, 10, 5, 1];
// a.sort() 的结果是什么？
```

**卡片背面：**

```js
[1, 10, 20, 5]
// sort() 默认会把所有元素当成字符串按字典序排列
```

当然，别光记坑，**还要考自己正确的解法怎么写：**

**卡片正面：**

```js
var a = [20, 10, 5, 1];
// 如何按数字大小升序排列？
```

**卡片背面：**

```js
function compare(v1, v2) { return (v1 - v2); }
a.sort(compare);
```

### 3. 把精妙的写法存成小挑战

如果平时读代码遇到了某个让你眼前一亮的巧妙写法，不妨把它变成一道编程小挑战的答案：

**卡片正面：**

```js
var albums = [
  {name: 'Beatles', title: 'White Album', price: 15},
  {name: 'Zeppelin', title: 'II', price: 7}
];
// 请实现 by 函数，使下面三行排序生效：
albums.sort(by('name'));
albums.sort(by('title'));
albums.sort(by('price'));
```

**卡片背面：**

```js
function by(propName) {
  return function(obj1, obj2) {
    v1 = obj1[propName];
    v2 = obj2[propName];
    if (v1 < v2) { return -1; }
    else if (v1 > v2) { return 1; }
    else { return 0; }
  };
}
```

### 4. 在题目里要求写出多种解法

如果同一件事有不止一种实现方式，而你希望两种都能信手拈来，那就直接在题干里要求“未来的自己”同时写出两种解法：

**卡片正面：**

```ruby
s = 'string like this'
# 在 Ruby 中，写出两种把它变成 'String Like This' 的方法
```

**卡片背面：**

```ruby
s.split.map(&:capitalize).join(' ')
s.gsub(/\b\S/) {|x| x.upcase}
```

### 5. 把抽象概念浓缩成极简示例

假设你刚花了 20 分钟钻研了一个偏底层的抽象概念（而不是某个具体的函数名）。很多时候，你只需要挑出一个最精炼的例子做成卡片，每次看到它，整个概念的来龙去脉就会瞬间在脑海里复原。

比如正则捕获组的嵌套顺序：

**卡片正面：**

```ruby
/(a(b)((c)d))/.match('abcd')
# $1, $2, $3, $4 分别是什么？
```

**卡片背面：**

```text
$1 = 'abcd'
$2 = 'b'
$3 = 'cd'
$4 = 'c'
```

再比如 Ruby 类定义中的 `self` 指向：

**卡片正面：**

```ruby
class C
  self
end
class D < C
end
d1 = D.new
# 此时 self 是哪个对象？
```

**卡片背面：**

```text
class D
```

### 6. 必读：Piotr Wozniak 的《知识拆解二十条准则》

关于如何把知识拆解成好卡片，最经典的指南莫过于 SuperMemo 创始人 Piotr Wozniak 写的《[知识拆解二十条准则（20 Rules of Formulating Knowledge）](https://www.supermemo.com/en/blog/twenty-rules-of-formulating-knowledge)》，强烈建议读一读。

## 第三步：每天雷打不动地刷完

要想让间隔重复发挥最大威力，请务必**每天打开软件复习一次**。如果三天打鱼两天晒网，一旦中断太久，所有卡片的复习节奏都会乱套，堆积如山的过期卡片会逼着你重新学一遍原本快记住的东西。

==每天只需要 20 分钟，你就能稳稳记住成千上万条这样的知识点。==

我直接把它变成了每天早上的固定仪式：烧一壶开水泡茶，趁着茶水晾凉的工夫刷完今天的 Anki，然后端起茶杯喝茶。

刷卡片的时候，不妨给自己加点紧迫感，逼自己用最快的速度抢答，肾上腺素飙升的感觉其实相当过瘾。

这就像是每天带大脑去趟健身房。每天只需高强度专注 20 分钟，无论是眼前的编码流畅度，还是长远的技术积累，回报都高得惊人。

平时只要学到新东西就随手加几张卡片进去，用不了多久你就会惊讶地发现：凡是你存进去过的知识，全都清晰如新地留在脑子里。
